# R24 — C++ Minimal Conforming Host

Status: **Complete — E24-1 through E24-8.** `GENIA_STATE.md` remains final
authority for implemented behavior. The skeptical completion audit records
PASS in `docs/analysis/r24-release-truth-audit.md`.

R24 establishes a genuine second Genia production host. The C++ host executes
a deliberately bounded, evidence-backed subset through the same required path:

```text
source -> parser -> approved portable Core IR -> evaluator -> normalized result
```

It is not a C++ dialect and does not define Genia semantics. The authoritative
contract and shared evidence remain in `m0smith/genia-2026`; implementation is
in `m0smith/genia-cpp`.

## Small runnable examples

With `genia-adapter` built from `m0smith/genia-cpp`, command mode executes exact
Integer arithmetic:

```console
$ genia-adapter -c '40 + 2'
42
```

The same host executes R21-R23 exact numeric behavior without routing exact
values through binary64:

```console
$ genia-adapter -c '[1.5 + 0.5, 1 / 2, float64(0)]'
[2.0, 1/2, float64(0.0)]
```

Both examples traverse the C++ parser, portable Core IR lowering, and evaluator.
They are representative of shared cases that pass in the pinned evidence; they
do not imply support for syntax or libraries outside the declared floor.

## Final capability floor

| Capability | R24 declaration | Evidence meaning |
| --- | --- | --- |
| `parser` | `supported` | The bounded parser surface is attempted case by case. |
| `ast_lowering` | `supported` | Implemented syntax lowers to approved portable Core IR. |
| `core_ir_eval` | `partial` | Only the bounded R24 evaluator surface is claimed. |
| `cli_command_mode` | `supported` | `-c` evidence passes. |
| `cli_file_mode` | `supported` | File-mode evidence passes. |
| `prelude_autoload` | `partial` | Only the bounded source-level prelude required by R24 is installed. |
| `shared_spec_runner` | `partial` | The external adapter participates deterministically in the generic runner. |
| `open_functions` | `supported` | Local grouped/repeated clauses pass; cross-module behavior remains gated by `multi_file_eval`. |

`core_ir_eval` is intentionally not promoted to `supported`. A passing case is
evidence for that case, not a feature-parity claim.

## Explicitly unsupported after R24

- R25 state/concurrency: refs, cells, processes, and actors.
- R26 REPL and broader data bridges.
- R27 Flow, pipe mode, HTTP serving, and outbound HTTP.
- Cross-module open-function contribution/selection and wider parser/evaluator
  behavior outside the R24 floor.
- General Option behavior, compatibility JSON, configuration/secrets, resource
  I/O, external execution, AI/retrieval providers, host interop, debugger/shell,
  browser runtime, and help parity.

Unsupported results are expected. R24 succeeds by proving one small portable
host boundary honestly, not by matching the Python host feature for feature.
