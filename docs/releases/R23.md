# R23 — Numeric Representation and Interchange

Status: **Complete — E23-1 through E23-11.** The skeptical release truth
audit gate found two genuine, narrow diagnostic-leak/doc-sync findings
during E23-7 and E23-9, both repaired (E23-8, E23-10) and both
re-verified; the third, independent re-audit (E23-11, issue #939) passed
cleanly. See `docs/analysis/r23-release-truth-audit.md` for the full
three-pass audit trail. `GENIA_STATE.md` sections 9.32-9.37 remain final
authority for implemented behavior; this document summarizes it.

R23 follows completed R21 and R22 (`docs/releases/R21.md`,
`docs/releases/R22.md`) and makes Genia's exact runtime numeric values
(Decimal/Rational/Float64) cross textual and JSON boundaries without
silently changing numeric domain or reintroducing implicit host
binary-float semantics.

The approved contract is
`docs/design/r23-numeric-representation-interchange-contract.md`.

## Scope landed so far (E23-1 through E23-6)

1. **Canonical display/debug rendering** (E23-1, issue #911) for Integer,
   Decimal, Rational, and Float64 -- fixed/scientific notation rules for
   Decimal, `<numerator>/<denominator>` for Rational, and an explicit
   `float64(<shortest-roundtrip-decimal>)` constructor-shaped atom for
   Float64, wired through the one shared `format_display`/`format_debug`
   rendering dispatch every user-facing and debug surface already uses.
2. **Existing field-format-spec integration** (E23-2, issue #913) against
   the E23-1 canonical renderer -- alignment/width, `.n` precision
   (half-up, from each kind's exact value), zero-padding, and grouping all
   now operate correctly against canonical Decimal/Rational/Float64 text,
   including two bug fixes (Float64 `.n` double-rounding via
   `repr(value)`; grouping corrupting the `float64(...)` wrapper text).
3. **Strict generic JSON boundary for Integer/Decimal** (E23-3, issue
   #915): the R9 safe-integer interval, the new `stable_json_decimal(d)`
   predicate, and lexical (never `float(...)`-mediated) JSON Decimal
   decode/encode for `json_decode`/`json_encode`.
4. **Strict generic JSON boundary for Rational/Float64** (E23-4, issue
   #921): a Rational encodes only when its exact value has a finite
   base-10 Decimal equivalent that itself satisfies `stable_json_decimal`;
   finite Float64 encodes via its canonical shortest-roundtrip spelling;
   NaN/infinity are rejected; JSON decode is confirmed to never construct
   Rational or Float64.
5. **Compatibility JSON reconciliation** (E23-5, issue #923):
   `json_parse`/`json_stringify`/`json_pretty`/`parse_jsonl_record` share
   the same lexical Decimal token parser as the strict boundary
   (deliberately without the `stable_json_decimal` stability gate, per
   compatibility JSON's legacy-tolerance character), and `json_stringify`
   now encodes `GeniaDecimal`/terminating `GeniaRational`/finite Float64
   using the same canonical-text computations as strict `json_encode`,
   closing a second contradictory host-float numeric model.
6. **Diagnostics normalization sweep + docs/release truth sync** (E23-6,
   issue #925): a full audit of every failure path E23-1 through E23-5
   touched or introduced. Format-spec and strict-JSON-boundary diagnostics
   were confirmed already portable (no raw host exception text crossing
   the boundary); the `json_number_out_of_range` reason-reuse question
   E23-3/E23-4 deferred was ratified as sufficient at the `reason` level
   and refined with an additive `cause` context field (never renaming the
   reason symbol); one genuine leak was found and fixed (compatibility
   `json_stringify`'s unsupported-value message used a raw Python
   `type(value).__name__` instead of the portable `_runtime_type_name`
   table); and the E23-4 `AssertionError` dead-code guard was confirmed
   genuinely unreachable through every public JSON entry point.

## Canonical rendering

```genia
500.0
-- 500.0   (Decimal, ".0" keeps it visibly distinct from Integer 500)

float64(0.1)
-- float64(0.1)
```

## JSON boundary

```genia
json_decode("1.5")
-- some(represent("json", 1.5), context)   -- exact Decimal, never a host float

json_encode(1 / 3)
-- err(unsupported_json_value, {value_type: "rational", ...})   -- non-terminating, never rounded

json_encode(9007199254740992)
-- err(json_number_out_of_range, {cause: "integer_out_of_range", ...})
```

## Diagnostics

Every numeric representation/interchange failure normalizes to a
structured Outcome or a clean, portable host exception message -- never
raw Python `decimal`/`fractions`/`json`/float-parser exception text or a
traceback. `json_number_out_of_range`'s several distinct underlying causes
(Integer range, Decimal/Rational instability, Float64 non-finite, and a
rejected non-finite JSON constant literal) are now additionally
distinguished by a `cause` context field, without changing the `reason`
symbol any existing code may already pattern-match on.

## Release truth audit (E23-7 through E23-11)

The skeptical release truth audit gate for R23 ran three independent
passes rather than a single rubber-stamp check:

- **E23-7 (issue #931) — original audit — FAIL.** Found one genuine leak:
  compatibility `json_stringify`'s diagnostics raw-leaked the Python
  class name `"GeniaRational"` instead of the portable type name
  `"rational"`.
- **E23-8 (issue #933) — repair.** Added a `GeniaRational -> "rational"`
  branch to `_runtime_type_name` in `src/genia/values.py`, fixing the
  leak across every "expected X, received Y" diagnostic in the codebase
  that shares this helper, not just `json_stringify`.
- **E23-9 (issue #935) — second, independent re-audit — FAIL.** Found
  that E23-8's own `GENIA_STATE.md` edit never narrated E23-8's own
  primary fix, a doc-sync gap under `AGENTS.md`'s "no exceptions"
  documentation-truth rule.
- **E23-10 (issue #937) — repair.** Added a clearly distinguished bullet
  to `GENIA_STATE.md` §9.37 describing the `GeniaRational -> "rational"`
  fix, plus a coverage-only extension to the generic diagnostic
  leak-sweep test's probed context keys.
- **E23-11 (issue #939) — third, independent re-audit — PASS.**
  Re-derived every contract section from scratch with new adversarial
  angles (module-level mutable-state/concurrency sweep, locale-
  independence grep, Rational-reduces-to-Integer rendering, computed
  Decimal negative-zero policy, exponent-leading-zero rule, negative-
  value half-up rounding, and every documented example run live against
  the CLI). Found no further defect. Full validation battery green.
