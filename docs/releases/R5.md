# R5 — Native Test Migration / Genia-Facing Coverage Wave 1

Status: Complete (issues #509–#518). See `docs/strategy/release-roadmap.md`
for full scope.

Theme: move appropriate Genia-facing tests into Genia-native tests, keeping
Python tests for Python host internals.

## What to run

R5's headline outcome is Genia-facing behavior (Outcome helpers, validation
helpers, Flow/Seq, Sheet helpers, prelude utilities) gaining native-test
coverage alongside — not instead of — the existing pytest suite. The
in-repo example is a native-test companion file for the tic-tac-toe example,
covering pure board/move logic:

```bash
genia test examples/tic_tac_toe_native_tests.genia
```

Output:

```text
total=6 passed=6 failed=0 errored=0
PASS winner_detects_row_column_and_diagonal_wins
PASS winner_reports_no_winner_on_open_board
PASS is_legal_move_checks_target_square_state
PASS set_at_replaces_only_the_targeted_index
PASS contains_empty_reports_whether_open_squares_remain
PASS next_player_alternates_marker
total=6 passed=6 failed=0 errored=0
```

The file at `examples/tic_tac_toe_native_tests.genia`
imports the existing `examples/tic-tac-toe.genia` example and asserts its
pure logic with `@test`-annotated functions ([R3](R3.md)), without driving
the interactive `input()`-based game loop — the pattern R5 asks new
Genia-facing coverage to follow.

## Native-test vs pytest boundary

R5 also produced the explicit rule for what belongs where:

- **Native tests (`genia test <file>`)**: Outcome helpers, validation
  helpers, Flow/Seq visible behavior, implemented Sheet helper behavior,
  prelude-level utilities, Genia-facing examples.
- **pytest**: parser internals, IR normalization, host adapter behavior, CLI
  harness internals, spec-runner implementation, Python-specific exceptions.
