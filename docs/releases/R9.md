# R9 — Value Templates & Representations

Status: **Active — E9-1 through E9-6 implemented**

E9-1 establishes the Experimental Template foundation without adding a second matcher or nominal type system. E9-2 adds Experimental ordered carrier facets and representation-aware matching through those same Templates. E9-3 adds Experimental refinement and open-map structural helpers. E9-4 adds exact ordinary-map structural matching. E9-5 adds a strict Outcome-native JSON representation boundary. E9-6 compiles a closed JSON Schema structural subset into those same Templates.

Run:

```bash
genia -c 'pattern Id(record) = some(record.id)
apply_template(template, value) = template(value)
[apply_template(Id, {id: 7, name: "Ada"}), {id: 7, name: "Ada"} @? Id]'
```

Output:

```text
[some(7), some({id: 7, name: "Ada"})]
```

The direct call exposes the matcher's `some(7)` payload. `@?` keeps its existing behavior and returns `some(original_subject)` on success.

## E9-2: generic carrier and matching

```genia
pattern Json(value) = representation_match("json", value)
read(value) =
  Json({id}) -> id

read(represent("json", {id: 7}))
```

Output:

```text
7
```

`represent` adds one explicit ordered outer facet. `representation_match`
removes only that requested outer layer for its named Template, so ordinary
patterns can destructure the carried value. `strip_representation` is the
separate explicit one-layer removal operation. Generic represented values
display opaquely as `<represented>`.

## E9-3: refinement and open structural Templates

```genia
pattern Present(value) = refinement_match((x) -> x != "", value)
pattern Adult(value) = refinement_match((age) -> age >= 18, value)
pattern Person(value) = open_shape_match({name: Present, age: Adult}, value)
Person({name: "Ada", age: 37, source: "csv"})
```

Output:

```text
some({name: "Ada", age: 37, source: "csv"})
```

An open shape requires its listed fields but accepts and preserves extras. Each
field value is checked by an existing Outcome Template. The helpers add no
shape declaration syntax or nominal record category.

## E9-4: exact/closed structural Templates

```genia
pattern Present(value) = refinement_match((x) -> x != "", value)
pattern Adult(value) = refinement_match((age) -> age >= 18, value)
pattern CleanPerson(value) = exact_shape_match({name: Present, age: Adult}, value)
[
  CleanPerson({name: "Ada", age: 37}),
  CleanPerson({name: "Ada", age: 37, source: "csv"})
]
```

Output:

```text
[some({name: "Ada", age: 37}), none("exact-shape-extra-field", {field: "source"})]
```

Exact matching requires precisely the specified field set and preserves the
original ordinary map on success. It adds no Struct object, constructor,
positional layout, or structural declaration syntax.

## E9-5: JSON representation boundary

```genia
decoded = json_decode("{\"name\":\"Ada\",\"age\":37}")
represented = unwrap_or({}, decoded)
representation_match("json", represented)
```

Output:

```text
some({name: "Ada", age: 37})
```

`json_decode` accepts JSON text or UTF-8 bytes and returns an Outcome whose
success value has exactly one outer `json` facet. `json_encode` accepts that
represented value or a supported ordinary value and returns deterministic
two-space-indented JSON. The portable boundary rejects duplicates, invalid
UTF-8/Unicode, unsafe integers, non-finite numbers, unsupported values, and
nesting beyond 128 containers with normalized `err` Outcomes. Legacy
`json_parse`, `json_stringify`, and JSONL behavior remains unchanged.

Protected facets and declassification remain later work.

## E9-6: JSON Schema structural subset

```genia
schema = json_decode("{\"type\":\"integer\"}")
Integer = json_schema(unwrap_or({}, schema)) |> unwrap_or((_) -> none("compile-failed"))
[Integer(7), Integer(1.5)]
```

Output:

```text
[some(7), none("json-schema-type-mismatch", {path: [], expected: integer, actual: number})]
```

`json_schema` accepts a `json`-represented schema map and returns an ordinary
callable Outcome Template. The implemented subset supports required `type`
with object properties/required names, array items, primitive checks, and
boolean `additionalProperties`. Every unlisted keyword fails explicitly; this
is not full JSON Schema conformance and adds no references, recursion,
coercion, defaults, generated classes, syntax, or schema-specific value model.
