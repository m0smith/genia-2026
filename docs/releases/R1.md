# R1 — Killer Workflow Foundation

Status: Complete. See `docs/strategy/release-roadmap.md` for full scope.

Theme: outcome-aware validated data pipelines — `messy records in → clear
pipelines → validated shaped output / reports + useful diagnostics`.

## What to run

R1's headline capability is validating a batch of records and getting back
both the clean records and structured diagnostics for the rest, using
`validate_record`, `validate_each`, and `collect_validated`.

```genia
valid_person(record) =
  validate_record(record, {
    id: (r) -> validate_required("id", r),
    name: (r) -> validate_required("name", r),
    age: (r) -> validate_field("age", (value) -> value >= 0, "age >= 0", r)
  })

records = [
  {id: 1, name: "Ada", age: 37},
  {id: 2, name: "", age: 12},
  {id: 3, name: "Grace", age: -1}
]

result = collect_validated(validate_each(records, valid_person))

print(result.clean)
print(result.diagnostics)
```

Run it:

```bash
genia path/to/this-file.genia
```

Output:

```text
[{id: 1, name: Ada, age: 37}, {id: 2, name: , age: 12}]
[{index: 2, kind: error, reason: record_validation_failed, context: some({diagnostics: [{field: age, status: error, reason: invalid field, context: {field: age, expected: age >= 0, actual: -1, reason: invalid field}}]})}]
```

Record `id: 2` passes `validate_required("name", r)` because the field is
merely present (an empty string, not absent) — `validate_required` checks
presence, not non-emptiness. Record `id: 3` fails the `age >= 0` field check
and shows up in `diagnostics` with the field-level reason instead of in
`clean`.
