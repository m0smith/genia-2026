# R17 — Numeric and Ordered-Map Portability Contract

Status: **Audit in progress — E17-0 through E17-2 are landed.**

R17 replaces two Python-host assumptions with explicit portable Genia semantics: arbitrary-precision integer arithmetic for the covered integer operators, and deterministic observable ordering for persistent maps. `GENIA_STATE.md` remains final authority.

## Integer arithmetic

Runnable example:

```genia
99999999999999999999999999999999 * 99999999999999999999999999999999
```

Output:

```text
9999999999999999999999999999999800000000000000000000000000000001
```

Ordinary Genia integer arithmetic for the R17-covered operators is mathematically exact and does not overflow, wrap, saturate, or truncate because of a host's fixed-width representation. This is independent of the existing R9 JSON safe-integer boundary, which remains limited to `json_encode` / `json_decode`.

## Ordered maps

Runnable example:

```genia
m = map_put(map_put(map_put(map_new(), "a", 1), "b", 2), "c", 3)
map_keys(map_put(m, "a", 99))
```

Output:

```text
["a", "b", "c"]
```

Replacing an existing key preserves its position. Removing a key preserves the relative order of the remaining keys, and re-inserting a removed key appends it at the end. `map_items`, `map_keys`, and `map_values` expose this deterministic order.

Map order remains distinct from map equality, map pattern matching, and `json_encode`'s sorted object-member output. Structural map equality is not defined by R17; the current Python-host identity-based `==` observation remains an unresolved follow-up.

## Release boundary

R17 adds no C++ implementation and does not change `/`, float semantics, Unicode semantics, diagnostics, JSON safe-integer limits, or map equality. Those remain outside this release.

The skeptical release audit and roadmap completion update are E17-3 / issue #780.
