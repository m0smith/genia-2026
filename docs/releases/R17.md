# R17 — Numeric and Ordered-Map Portability Contract

Status: **Complete — E17-0 through E17-3 (#777–#780) delivered. The skeptical
release truth audit recorded a PASS verdict.**

R17 makes arbitrary-precision integer arithmetic and deterministic ordered-map
behavior explicit portable contracts. It adds shared evidence and authoritative
documentation, not new Python runtime behavior, Core IR behavior, or a C++ host.
`GENIA_STATE.md` remains final authority; the approved boundary is recorded in
`docs/design/r17-numeric-ordered-map-portability-contract.md`.

## Exact integer arithmetic

Genia integers exclude booleans and are arbitrary precision. For `+`, `-`, `*`,
`%`, unary `-`, `<`, `<=`, `>`, and `>=`, integer results are mathematically
exact regardless of magnitude; a host must not silently narrow them to a
fixed-width representation.

Run:

```genia
99999999999999999999999999999999 * 99999999999999999999999999999999
```

Output:

```text
9999999999999999999999999999999800000000000000000000000000000001
```

This does not change R9's JSON safe-integer domain
`[-9007199254740991, 9007199254740991]`, which applies only at the documented
`json_encode`/`json_decode` boundary. Division and float-producing behavior are
outside R17.

## Deterministic map order

`map_new()` starts empty. A new key appends; replacing a present key preserves
its position; removal preserves the remaining relative order; removing an
absent key does not change order; and reinserting a removed key appends it.
Map literals associate left-to-right, with a repeated key taking its last value
while retaining its first-associated position. `map_items`, `map_keys`, and
`map_values` expose this order.

Replacing a value does not move its key:

```genia
m = map_put(map_put(map_put(map_new(), "a", 1), "b", 2), "c", 3)
map_keys(map_put(m, "a", 99))
```

Output:

```text
["a", "b", "c"]
```

Removing and reinserting appends at the current end:

```genia
m = map_put(map_put(map_put(map_new(), "a", 1), "b", 2), "c", 3)
map_keys(map_put(map_remove(m, "b"), "b", 200))
```

Output:

```text
["a", "c", "b"]
```

Map order remains distinct from map pattern matching and `json_encode`'s sorted
object-member-name output. Map equality also remains unresolved: the current
Python host's identity-based `==` observation for separately created maps is not
portable structural-equality semantics, and R17 does not change `==`.

## Skeptical release audit

The E17-3 audit checked the approved contract, the three R17 shared eval cases,
the Python reference-host paths they exercise, authoritative documentation,
release examples, navigation, roadmap claims, and the R9/R16/R18/R19/R20 scope
boundaries. The committed E17-0 through E17-2 changes contain no C++
implementation and no runtime implementation change.

The temporary R17 handoff directory was absent at audit start, including the
reported but uncommitted `06-doc-sync.md`. In accordance with the requirement
not to invent historical artifacts, the audit relied only on independently
verifiable commits, contract text, shared specs, source inspection, and freshly
observed validation. GitHub PR/CI status could not be independently queried from
this unauthenticated checkout, so it was not used as PASS evidence.

**Verdict: PASS.** The written R17 contract specifies the representation-neutral
integer and ordered-map invariants, and the shared cases provide executable
observable examples. A future non-Python host can therefore choose its integer
and ordered-map representations from that contract plus shared specs and
reproduce the required behavior without consulting Python implementation
details. R17 is ready to merge; map equality remains a separately gated open
question.
