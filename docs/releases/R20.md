# R20 — Open Functions and Extensible Pattern Dispatch

Status: **Complete — E20-1 through E20-8.** The skeptical release truth
audit (E20-8) verdict and evidence are recorded in
`docs/analysis/r20-release-truth-audit.md`. `GENIA_STATE.md` section 4.7
remains final authority for implemented behavior; this document summarizes
it.

R20 follows completed R16 Multi-Host Conformance Infrastructure through R19
Unicode and Diagnostic Portability. Its purpose is one portable semantic
addition: a named, lexically visible **open function interface** that can
own ordered local pattern clauses and receive explicitly selected, immutable
cross-module clause contributions — without adding methods, protocols,
type-directed dispatch, or a mutable global registry.

The approved semantic contract is `docs/design/r20-open-functions-contract.md`
(E20-0). The approved surface syntax and Core IR are
`docs/design/r20-open-functions-syntax-ir-design.md` (E20-1).

## Scope

R20 covers:

1. Repeated local pattern-dispatched clauses accumulating into one named
   interface, equivalent to the existing grouped case-with-`|` spelling.
2. Explicitly selected cross-module contributions extending an open
   function, never through implicit/ordinary `import`.
3. Deterministic, host-independent dispatch and ambiguity/duplicate
   behavior, with no import-order or selection-order priority.
4. Stable interface identity independent of import aliases, host object
   identity, filesystem paths, and import order.
5. Provenance sufficient for diagnostics and introspection (`help`).
6. Inert declaration/import/linking behavior.
7. Portable shared evidence (parse, IR, eval, error) for a future non-Python
   host, plus a dedicated `open_functions` host capability.

R20 explicitly does **not** include protocols/interfaces/typeclasses, object
methods, dynamic runtime registration, mutable global dispatch registries,
`==` overloading, lifecycle activation, module unloading/reloading,
actor/concurrency work, or a C++ host implementation (R21).

## Syntax

```genia
open gcd(a, 0) = a
gcd(a, b) = gcd(b, a % b)

gcd(48, 18)
-- 6
```

is exactly equivalent to the grouped spelling:

```genia
open gcd(a, b) = (a, 0) -> a | (a, b) -> gcd(b, a % b)
```

Explicit cross-module contribution and selection:

```genia
# base.genia
open get("mem", store, key) = "mem:" + key

# db_ext.genia
import base
extend base.get("db", db, key) = "db:" + key

# consumer.genia
import base
import db_ext

use get from base with db_ext

get("mem", "x", "k1")   -- "mem:k1"
get("db", 1, "k2")      -- "db:k2"
```

Ordinary `import db_ext` alone never extends `base.get`; only the explicit
`use ... from ... with ...` statement, in the module that writes it, links
the selected contribution(s) into one immutable view bound to that module's
own `get` name.

See `GENIA_STATE.md` section 4.7 for the complete rule set (dispatch
algorithm, duplicate-clause detection, diagnostics, provenance/`help`,
inertness, and this Experimental slice's disclosed known limitations).

## Core IR

Three new portable node types, added to `src/genia/ir.py` and
`docs/architecture/core-ir-portability.md`:

- `IrOpenFuncDef(name, clauses, docstring, annotations)`
- `IrOpenContribution(target_module_alias, target_name, clauses)`
- `IrOpenUse(local_name, target_module_alias, target_name, contribution_module_aliases)`

Every clause is an ordinary `IrCaseClause` over an `IrPatTuple` pattern,
reused verbatim from the existing case-dispatch representation — R20 adds
no new pattern or guard node. No existing node changed shape.

## Conformance evidence

- **Parse** (`spec/parse/parse-r20-*.yaml`, `parse-error-r20-*.yaml`, 9
  cases): repeated/grouped-flattened clause forms, `extend`, `use`,
  ordinary-`FuncDef` non-regression, and four rejection forms
  (redeclaration, doubly-qualified `extend` target, nested `open`, `use`
  missing `with`).
- **IR** (`spec/ir/r20-*.yaml`, 5 cases): repeated-clause normalization,
  grouped/repeated equivalence (byte-identical clause lists), `extend`,
  `use`, and a varargs (`..rest`) shape.
- **Eval** (`spec/eval/r20-*.yaml`, 9 cases): the four local cases plus five
  portable logical multi-file cases covering explicit disjoint selection,
  import/selection order independence, alias/interface identity, lexical
  visibility, and consumer non-transitivity.
- **Error** (`spec/error/error-r20-*.yaml`, 6 cases): the three local failures
  plus portable duplicate-alias selection, incompatible-target, and
  overlapping-unit ambiguity diagnostics.
- All 29 cases require `open_functions`; the eight multi-file cases also
  require the R16 infrastructure capability `multi_file_eval`. The Python reference
  host declares that capability `supported`
  (`spec/manifest.json`, `docs/host-interop/HOST_CAPABILITY_MATRIX.md`), so
  an older/non-conforming host reports them unsupported rather than
  silently passing.
- **Cross-module contribution/linking** retains Python real-file unit evidence
  and now also has eight host-neutral eval/error cases using #836's logical
  multi-file fixture. The fixture contract transports relative logical paths,
  contents, and an entry file through both in-process and R16 subprocess
  paths; Python temporary-directory realization is private adapter behavior.

## What is implemented vs. what remains

Implemented and tested:

- local repeated/grouped clause accumulation and dispatch, including
  fixed-over-varargs precedence and varargs-shape ambiguity;
- structural, alpha-normalized, span-free duplicate-clause detection at
  unit-build time;
- explicit `extend`/`use` cross-module contribution and linking, with
  import/selection-order independence, alias identity, and non-transitive
  linked-view scope;
- `help()` provenance listing (interface name, span, docstring, and every
  participating unit's clause spans in deterministic order);
- a dedicated `open_functions` host capability so unsupported hosts cannot
  silently pass R20 cases;
- full existing-suite regression (see the audit for exact counts).

Not implemented / explicitly out of scope for this release:

- `@doc`/`@meta`-style annotation attachment on `open`/`extend`
  declarations beyond the optional leading docstring position;
- any specificity/priority ranking between overlapping contributions —
  overlap is ambiguity, by design;
- a second production host (C++ is R21, and only after its own gates run);
- debug-hook (`debug_hooks`/`debug_mode`) propagation through open-function
  dispatch;
- grouped case-body flattening for a non-trivial (pattern-bearing) clause
  header — rejected rather than given ad hoc semantics.

Python remains the only implemented production host. R20's 29 shared
parse/IR/eval/error cases are the portable record a future host implements
against; the additional real-file unit evidence does not make filesystem
behavior portable and does not constitute another implemented host.
