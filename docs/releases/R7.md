# R7 — Web Serving Ergonomics

Status: **Active.** Issues #526 and #527 provide response-header composition and the CORS handler wrapper. Capability stabilization remains owned by #530.

Theme: make the existing Python-host HTTP surface comfortable for a real browser client without creating a general web framework.

## Landed: response-header composition (issue #526)

`web.with_headers(headers, response)` returns a new response, normalizes header names to lowercase, and lets supplied values win case-insensitive collisions:

```genia
import web

response = web.json({message: "hello"})
  |> web.with_headers({"X-Request-ID": "abc123"})

[
  response("status"),
  response("headers")("content-type"),
  response("headers")("x-request-id")
]
```

Run it:

```bash
genia path/to/this-file.genia
```

Observed output:

```text
[200, "application/json; charset=utf-8", "abc123"]
```

The helper preserves status, body, and additional response fields without mutating either input. It is **Python-host-only** and Partial. It does not itself add CORS, an `OPTIONS` route, middleware, or header-taking `json`/`text` overloads.

## Landed: CORS handler wrapper (issue #527)

`examples/http_service.genia` wraps its route handler once with `web.cors`. Its application handlers still return ordinary `web.json` and `web.ok_text` responses and construct no CORS headers.

Run two requests and stop:

```bash
genia examples/http_service.genia --max-requests 2
```

In another terminal, send a browser-shaped preflight followed by a JSON request:

```bash
curl -i -X OPTIONS http://127.0.0.1:8080/info \
  -H 'Origin: http://localhost:5173' \
  -H 'Access-Control-Request-Method: GET'
curl -i http://127.0.0.1:8080/info \
  -H 'Origin: http://localhost:5173'
```

The preflight returns `204` with `access-control-allow-origin`, `access-control-allow-methods`, and `access-control-allow-headers`. The JSON request returns the application body with both `application/json; charset=utf-8` and the configured CORS headers.

`web.cors(policy, handler)` is **Python-host-only** and Partial. Its closed policy accepts optional `origin`, `methods`, and `headers`; incomplete `OPTIONS` requests delegate normally. It does not add credentials, dynamic origin reflection, allowlists, per-route overrides, a public `options(...)` route, or a general middleware framework.
