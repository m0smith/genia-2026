Theme: make validated pipelines feel production-useful.

## Landed so far: CSV row parsing (issue #390)

`parse_csv_row` (**Experimental**) parses one CSV row string into an
Outcome, composing directly with the [R1](R1.md) validation pipeline
(`validate_each` / `collect_validated`):

```genia
result = collect_validated(
  validate_each(
    [
      parse_csv_row(["name", "age"], "Ada,37"),
      parse_csv_row(["name", "age"], "   "),
      parse_csv_row(["name", "age"], "\"unterminated")
    ],
    (record) -> some(record)
  )
)

print(result.clean)
print(result.diagnostics)
```

Run it:

```bash
genia path/to/this-file.genia
```

Output:

```text
[{name: Ada, age: 37}]
[{index: 1, kind: skipped, reason: blank_line, context: some({kind: csv_row, status: skipped, reason: blank_line, line:    })}, {index: 2, kind: error, reason: invalid_csv_row, context: some({kind: csv_row, status: error, reason: invalid_csv_row, line: "unterminated, message: unterminated quoted field})}]
```

The three input rows show the three outcomes `parse_csv_row` can produce: a
valid row parsed into a header-mapped record, a blank line skipped as
`none("blank_line", ...)`, and a malformed row (unterminated quote) reported
as `err("invalid_csv_row", ...)` — all three flow through the same
`validate_each`/`collect_validated` pipeline from R1 without special-casing.

`parse_csv_row` is a one-row helper, not a CSV framework: it does not read
whole files, trim fields, infer types, or support multiline fields. See
`README.md` for the full contract.

## Landed: stable validation diagnostic layers (issue #405)

Validation diagnostic fields remain **Experimental**, but their stable fields
are now defined per producing layer. This example shows caller context on the
record failure, a field diagnostic, and the helper-owned context nested inside
it:

```genia
validate_record(
  {row: 12, age: "old"},
  {
    age: (record) -> validate_field(
      "age",
      (value) -> value > 0,
      "positive number",
      record
    )
  },
  {source: "csv"}
)
```

Run it:

```bash
genia -c 'validate_record({row: 12, age: "old"}, {age: (record) -> validate_field("age", (value) -> value > 0, "positive number", record)}, {source: "csv"})'
```

Output:

```text
err(record_validation_failed, {source: "csv", diagnostics: [{field: "age", status: error, reason: "invalid field", context: {row: 12, field: "age", expected: "positive number", actual: "old", reason: "invalid field"}}]})
```

There is no universal validation diagnostic schema. Helper context,
`validate_record` field diagnostics, and `collect_validated` aggregate
diagnostics remain distinct layers; caller and nested context are preserved
rather than flattened.

## Landed: field/index validation diagnostic helpers (issue #393)

Small **Experimental** constructors create explicit diagnostic maps, and focused
accessors retrieve their field and reason:

```genia
d = diagnostic_error(2, "age", quote(out_of_range), {actual: -1})
[d, diagnostic_field(d), diagnostic_reason(d)]
```

Run it:

```bash
genia -c 'd = diagnostic_error(2, "age", quote(out_of_range), {actual: -1}); [d, diagnostic_field(d), diagnostic_reason(d)]'
```

Output:

```text
[{index: 2, field: "age", kind: error, reason: out_of_range, context: {actual: -1}}, "age", out_of_range]
```

`diagnostic_skipped` produces the same five-key shape with `kind: skipped`.
Constructor arguments are preserved without coercion or context wrapping. These
helpers create and inspect ordinary maps; they do not change or automatically
integrate with `validate_record` or `collect_validated` diagnostics.

## Landed: collect_sheet Sheet conversion (issue #395)

`collect_sheet(records)` (**Experimental**) is the explicit landing-zone step after
`collect_validated`: it converts a finite list or Flow of homogeneous map records into
an immutable Sheet, using the first record's key order as column order.

```genia
validated = collect_validated(
  validate_each(
    [{name: "Ann", age: 30}, {name: "Bob", age: 22}],
    (record) -> some(record)
  )
)
report = collect_sheet(map_get(validated, "clean"))

print(shape(report))
print(columns(report))
print(rows(report))
```

Run it:

```bash
genia path/to/this-file.genia
```

Output:

```text
[[rows, 2], [columns, 2]]
[name, age]
[[[name, Ann], [age, 30]], [[name, Bob], [age, 22]]]
[[["name", "Ann"], ["age", 30]], [["name", "Bob"], ["age", 22]]]
```

The first three lines are the explicit `print` calls; the fourth line is the file's
final-expression auto-print, showing `rows(report)` again in debug format — note
column names here are plain strings (`"name"`, `"age"`), not symbols, because map
literal keys such as `{name: ...}` evaluate to strings; `sheet(...)`'s own
`quote(name)`-keyed columns still render as bare symbols.

`collect_sheet` does not read or unwrap Outcome values and does not aggregate
diagnostics — `collect_validated` remains the separate, explicit aggregation step.
See `README.md` for the full contract, including exact-shape column validation and
error behavior.
