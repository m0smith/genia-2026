## Release purpose and delivered scope

R29 gives Outcome-aware validated pipelines an explicit Sheet-to-record boundary. On the **Python reference host**, the **Experimental** `sheet_records/1` builtin eagerly materializes a reusable List of distinct row Maps. It preserves row order, column order, and the exact keys and cell values. The input stays immutable. Outcome cells remain data, and protected cells remain opaque under existing sink rules.

Zero rows produce `[]` and lose the column schema. A Sheet with rows and no columns yields one empty Map per row. Unchanged nonempty records can reconstruct the Sheet using `collect_sheet`. Non-Sheet input raises the marked `TypeError("sheet_records expected a Sheet")`. Sheets remain non-Seq. Bounds applied to a downstream Flow cannot reduce the conversion's eager allocation.

The [validated report proving case](https://github.com/m0smith/genia-2026/blob/e9f3b7d33f34d7065e1ab22c5eb16ddb2109fe93/spec/eval/r29-records-validated-report.yaml) exercises the boundary with existing validation and collection. Callers supply validation and pass `collect_validated(results).clean` to `collect_sheet`. Existing Flow, Outcome, lifecycle and name-resolution rules continue to govern composition. R29 adds one builtin and its governed MCP allowlist entry. AWK syntax, implicit Sheet iteration, a new List-to-Flow bridge, shaped column computations and relational operations are outside this release.
