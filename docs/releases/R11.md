# R11 — AI Composition

Status: **Active — E11-1 through E11-7 delivered; E11-8 remains planned**

All R11 APIs remain **Experimental**. Portable semantics cover the closed
ordinary values, callable model, existing Outcomes, one-attempt rule, R9/R10
composition, and application-owned list/Flow state evolution. The deterministic
fixture and Gemini REST providers are **Python-host-only** capabilities; other
hosts and provider adapters are not implemented.

The composition rule is deliberately small: messages are ordinary values,
prompts are functions, models are callable, chains are pipelines, and
conversations are application composition over `scan`.

E11-1 adds one Experimental public entry point, `model/4`, which returns an
ordinary callable over ordinary text request/response values and existing
Outcomes. The only implemented provider is an explicit deterministic Python
test fixture; this slice performs no network operation and supplies no ambient
provider, credential, or authority.

E11-2 adds the closed JSON output requirement and reuses R9 `json_schema`,
`json_decode`, represented values, callable Templates, and Outcomes. It adds no
AI-specific schema, validator, repair, or retry subsystem.

E11-3 adds one explicitly host-constructed Google Gemini Developer API
capability using direct standard-library `v1beta models.generateContent` REST.
It preserves R10 just-in-time declassification and one-attempt behavior, adds no
SDK or general HTTP API, and uses an injected offline fake transport in automated
tests. Because ordinary source cannot construct host capabilities, E11-3 adds no
new standalone source-only example; the runnable fixture examples below are the
truthful public `model/4` demonstrations. E11-7 verifies these examples and
synchronizes this public account; it adds no runtime behavior.

E11-4 adds shared eval, error, Flow, CLI, parse, and Core IR conformance
coverage. Its CLI command/file/pipe fixture selection exists only in the shared
test harness; ordinary execution still receives no ambient model provider,
credential, or authority.

E11-5 adds no API. `examples/r11_flow_conversation.genia` demonstrates an
application-defined step over the exact ordinary conversation state and input
values. Existing `scan` supplies eager list and lazy Flow composition; stop and
failed states are inert, and input acquisition remains external. Run its focused
executable proof with:

```bash
uv run pytest -q tests/unit/test_r11_flow_conversation_615.py
```

The observed proof covers successful and failed/absent model Outcomes, explicit
stop, list/Flow equivalence, source independence, lazy bounded attempts, and
post-terminal no-call behavior.

The application source is also directly runnable with the explicit fixture
harness:

```bash
uv run python -m hosts.python.exec_model_fixture --file examples/r11_flow_conversation.genia
```

Output:

```text
<function conversation_step/4>
```

That output confirms the file defines the ordinary application step; the
focused test command above executes its list/Flow transitions and asserts exact
states.

E11-6 adds the focused executable validated-pipeline proof:

```bash
uv run python -m hosts.python.exec_model_fixture --file examples/r11_validated_pipeline_proving_case.genia
```

It composes mixed JSONL parsing, existing record validation, an ordinary
structured model stage, R9 JSON/Templates, explicit R10 protected credentials,
and `collect_validated`. The deterministic result contains two clean represented
values and three ordered diagnostics; tests also cover normalized model and
protected-boundary failures without retry or leakage.

Output:

```text
{clean: [<represented>, <represented>], diagnostics: [{index: 1, kind: skipped, reason: "blank_line", context: some({kind: jsonl_record, status: skipped, reason: blank_line, line: ""})}, {index: 2, kind: error, reason: invalid_jsonl_record, context: some({kind: jsonl_record, status: error, reason: invalid_jsonl_record, line: "not-json", message: "Expecting value", column: 1})}, {index: 3, kind: error, reason: record_validation_failed, context: some({diagnostics: [{field: "name", status: error, reason: "missing required field", context: {field: "name", reason: "missing required field"}}]})}]}
```

Run the fixture example from the repository:

```bash
uv run python -m hosts.python.exec_model_fixture 'm = model(model_provider_fixture, {id: "fixture-text", timeout_ms: 1000}, model_credential_fixture, model_authority_fixture)
m({messages: [{role: quote(user), content: {kind: quote(text), text: "hello"}}], output: {kind: quote(text)}})'
```

Output:

```text
some({message: {role: assistant, content: {kind: text, text: "fixture reply"}}, finish_reason: stop, usage: some({input_tokens: 2, output_tokens: 3, total_tokens: 5})})
```

The request is validated before credential declassification, audit, or provider
attempt. A valid invocation declassifies through the existing R10 authority and
makes exactly one synchronous attempt; it never retries. Results use existing
`some`, `none`, and `err` values with the closed E11-1 response and failure
shapes documented in `GENIA_STATE.md` and `GENIA_RULES.md`.

Run the structured fixture example:

```bash
uv run python -m hosts.python.exec_model_fixture 'schema = json_decode("{\"type\":\"integer\"}") |> unwrap_or({})
Integer = json_schema(schema) |> unwrap_or((_) -> none("compile-failed"))
m = model(model_provider_fixture, {id: "fixture-json", timeout_ms: 1000}, model_credential_fixture, model_authority_fixture)
response = m({messages: [{role: quote(user), content: {kind: quote(text), text: "Return 7"}}], output: {kind: quote(json), schema: schema, template: Integer}}) |> unwrap_or({})
response("message")("content")("value") |> representation_match("json") |> unwrap_or(-1)'
```

Output:

```text
7
```

This page does not claim R11 completion. Tools, agents, streaming, retries,
fallback, a provider registry, multimodal content, persistent memory, and RAG
are not implemented. Retrieval, embeddings, grounding, and citations remain
R12 planning. E11-8 remains separately gated.
