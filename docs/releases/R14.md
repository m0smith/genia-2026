# R14 — Composable Lifecycles

Status: **Active — E14-1 delivered**

The delivered E14-1 APIs are **Experimental**. Portable root/child execution-
scope semantics are implemented by the Python reference host; Python is the
only implemented host and shared/multi-host conformance remains Partial.

Run:

```bash
genia -c 'parent = {name: quote(parent), enter: (_) -> some("ctx"), exit: (_, _) -> some("nil")}
root = lifecycle_scope([parent], (scope) -> lifecycle_child(scope, [], (child) -> lifecycle_context(child, quote(parent))))
child = root.result |> unwrap_or(none)
[root.status, child.status, child.scope, child.result]'
```

Output:

```text
[ok, ok, child, some(some("ctx"))]
```

`lifecycle_scope` enters an explicit root lifetime. `lifecycle_child` runs and
fully unwinds a synchronous child before returning its ordinary
`LifecycleResult`; a failed child does not implicitly fail its parent.
`lifecycle_context` reads context inward through the explicit opaque handle,
and a handle used after its scope ends raises `lifecycle-scope-expired`.

Peers enter in list order and entered peers unwind in reverse order. Cleanup
continues after failure without replacing the first primary failure. Lifecycle
definitions and imports remain inert until an explicit scope call consumes
them.

E14-1 does not implement repeated element scopes, Flow/Seq integration,
lifecycle-owned configuration, outbound HTTP, HTTP annotations, server/request
composition, ambient context, a generalized R4 plan runner, concurrency, or
cancellation. Those remain later gated R14 slices.
