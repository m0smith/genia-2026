# R13 — Configuration Resolution Ergonomics

Status: **Active — E13-1 through E13-7 delivered; E13-8 remains separately gated**

The delivered APIs remain **Experimental**. Portable ordinary callable and
Outcome behavior composes explicit providers, immutable snapshots, qualified
views, explicit conversion and callable Template validation, and unchanged R10
protected values. Environment and exact-path `.env` acquisition plus the
authority/outbound test seams are **Python-host-only**; Python is the only
implemented host and shared/multi-host conformance remains Partial.

The conventional fixed precedence is overrides > explicit arguments > environment
> `.env`. E13-7 verifies the public examples and this implemented-truth account
without adding runtime behavior.

Run:

```bash
genia -c 'provider = config_provider([{kind: quote(values), values: {SERVER_PORT: "8080", DB_PORT: "5432"}}]) |> unwrap_or(none)
server = config_view(provider, "SERVER_")
database = config_view(provider, "DB_")
[server("PORT"), database("PORT")]'
```

Output:

```text
[some("8080"), some("5432")]
```

`config_view(provider, prefix)` and
`secret_view(provider, prefix, purpose)` validate and capture their arguments
without lookup or host effects. Each returned one-argument callable forms the
physical key by exact prefix/name concatenation and delegates once to the
existing `config_get` or `secret_get`. Outcomes and every R10 secret-protection
boundary remain unchanged.

E13-1 itself adds no source adapter, `.env` support, conventional provider, caching,
fallback, conversion, Template validation, ambient lookup, `server.PORT`
member access, lifecycle binding, or dependency injection; E13-3 separately
delivers only the narrow `.env` source described below.

## E13-2 — explicit CLI configuration source

Run:

```bash
genia -c 'config_args(argv())' -- --server-port 8080 -- input.jsonl
```

Output:

```text
some({kind: values, values: {SERVER_PORT: "8080"}})
```

`config_args(args)` consumes only its explicit string list. Before standalone
`--`, it accepts long option/value pairs, normalizes ASCII names to uppercase
underscore keys, preserves exact values, rejects repeated normalized keys, and
returns the existing R10 literal source descriptor inside `some(...)`.
Malformed string data returns non-sensitive `config-source-invalid`; invalid
input types are runtime misuse.

E13-2 does not read process arguments itself, interpret Genia mode flags,
construct a provider, add a host capability, validate unknown option names,
encode boolean flags, or convert values.

## E13-3 — narrow `.env` source capability

Run from the repository root:

```bash
genia -c 'provider = config_provider([{kind: quote(dotenv), path: "examples/r13_dotenv_example.env", required: true}]) |> unwrap_or(none)
config_get(provider, "SERVER_PORT")'
```

Output:

```text
some("8080")
```

The descriptor snapshots one exact path during provider construction. Portable
semantics own strict UTF-8 decoding, the narrow E13-3 line/key/value grammar,
fixed source ordering, immutable lookup, and non-sensitive failure Outcomes;
the Python host owns filesystem byte acquisition. Optional absence is an empty
source. Required absence/read failure, unavailable capability, invalid UTF-8,
and invalid grammar remain distinct.

E13-3 adds no discovery, `.env.local`/profile cascade, interpolation,
expansion, command substitution, multiline value, refresh/watch behavior, or
public parser.

## E13-4 — conventional provider composition

Run from the repository root:

```bash
genia -c 'provider = config_standard({SERVER_PORT: "9000"}, ["--db-port", "5432"]) |> unwrap_or(none)
[config_get(provider, "SERVER_PORT"), config_get(provider, "DB_PORT")]'
```

Output:

```text
[some("9000"), some("5432")]
```

`config_standard` delegates to the existing provider using fixed indices and
precedence: overrides > explicit arguments > environment > `.env`. Its
two-argument form uses optional `.env`; a third explicit path is required.
Construction remains atomic and immutable, and returns the exact existing
provider Outcome.

## E13-5 — cross-mode and protected-boundary hardening

E13-5 adds verification rather than a second API. Shared eval/error/CLI/parse/IR
cases prove explicit construction, exact existing Outcomes, normalized failures,
command-mode behavior, and ordinary call lowering. Focused Python-host tests
prove snapshot-before-use/no-refresh behavior through qualified views, imports,
native-test and serve seams, while the unchanged R10 protection suites cover
recursive diagnostic, report, resource, HTTP, and ordinary-host boundaries.

No public example is added for this internal hardening slice. E13-6 owns the
Outcome-aware validated-pipeline proving case.

## E13-6 — Outcome-aware validated-pipeline proving case

Run from the repository root:

```bash
genia examples/r13_validated_pipeline_proving_case.genia
```

Output:

```text
{server_port: some(8080), database_port: some(5432), metrics_port: some(9100), clean: [{id: 1, name: "Ada"}, {id: 2, name: "Grace"}], diagnostics: [{index: 1, kind: skipped, reason: "blank_line", context: none("nil")}, {index: 2, kind: error, reason: record_validation_failed, context: some({diagnostics: [{field: "name", status: error, reason: "missing required field", context: {field: "name", reason: "missing required field"}}]})}], credential: "<protected>", protected_match: true}
```

This offline application proof composes one conventional provider, distinct
qualified server/database/metrics `PORT` values, explicit integer conversion,
callable Template validation, and existing record collection into clean values
plus ordered diagnostics. The public result never reveals the protected
credential. Focused Python-host tests inject an authority and outbound fixture:
the matching boundary audits, declassifies, and attempts exactly once; mismatch,
provider failure, and direct protected submission remain effect-free and
non-revealing.

E13-6 adds no API, runtime semantics, networking, retry, fallback, ambient
provider, or lifecycle behavior.

R13 remains active and E13-8 remains separately gated. E13-7 adds no runtime
behavior, and this page does not claim dot access, ambient lookup, lifecycle injection
or lifecycle provider binding, dependency injection, `.env` discovery,
interpolation, expansion, profiles or cascades, refresh/watch behavior,
configuration schemas, implicit conversion, remote stores, or a broad
configuration framework.
