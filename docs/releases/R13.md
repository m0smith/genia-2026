# R13 — Configuration Resolution Ergonomics

Status: **Active — E13-1 through E13-4 delivered**

The delivered APIs are **Experimental**. They are portable ordinary callable
behavior over the existing R10 provider and protected-value contract. Python is
the only implemented host; no new host capability, syntax, named access, or
Core IR node is added.

Run:

```bash
genia -c 'provider = config_provider([{kind: quote(values), values: {SERVER_PORT: "8080", DB_PORT: "5432"}}]) |> unwrap_or(none)
server = config_view(provider, "SERVER_")
database = config_view(provider, "DB_")
[server("PORT"), database("PORT")]'
```

Output:

```text
[some("8080"), some("5432")]
```

`config_view(provider, prefix)` and
`secret_view(provider, prefix, purpose)` validate and capture their arguments
without lookup or host effects. Each returned one-argument callable forms the
physical key by exact prefix/name concatenation and delegates once to the
existing `config_get` or `secret_get`. Outcomes and every R10 secret-protection
boundary remain unchanged.

E13-1 itself adds no source adapter, `.env` support, conventional provider, caching,
fallback, conversion, Template validation, ambient lookup, `server.PORT`
member access, lifecycle binding, or dependency injection; E13-3 separately
delivers only the narrow `.env` source described below.

## E13-2 — explicit CLI configuration source

Run:

```bash
genia -c 'config_args(argv())' -- --server-port 8080 -- input.jsonl
```

Output:

```text
some({kind: values, values: {SERVER_PORT: "8080"}})
```

`config_args(args)` consumes only its explicit string list. Before standalone
`--`, it accepts long option/value pairs, normalizes ASCII names to uppercase
underscore keys, preserves exact values, rejects repeated normalized keys, and
returns the existing R10 literal source descriptor inside `some(...)`.
Malformed string data returns non-sensitive `config-source-invalid`; invalid
input types are runtime misuse.

E13-2 does not read process arguments itself, interpret Genia mode flags,
construct a provider, add a host capability, validate unknown option names,
encode boolean flags, or convert values.

## E13-3 — narrow `.env` source capability

Run from the repository root:

```bash
genia -c 'provider = config_provider([{kind: quote(dotenv), path: "examples/r13_dotenv_example.env", required: true}]) |> unwrap_or(none)
config_get(provider, "SERVER_PORT")'
```

Output:

```text
some("8080")
```

The descriptor snapshots one exact path during provider construction. Portable
semantics own strict UTF-8 decoding, the narrow E13-3 line/key/value grammar,
fixed source ordering, immutable lookup, and non-sensitive failure Outcomes;
the Python host owns filesystem byte acquisition. Optional absence is an empty
source. Required absence/read failure, unavailable capability, invalid UTF-8,
and invalid grammar remain distinct.

E13-3 adds no discovery, `.env.local`/profile cascade, interpolation,
expansion, command substitution, multiline value, refresh/watch behavior, or
public parser.

## E13-4 — conventional provider composition

Run from the repository root:

```bash
genia -c 'provider = config_standard({SERVER_PORT: "9000"}, ["--db-port", "5432"]) |> unwrap_or(none)
[config_get(provider, "SERVER_PORT"), config_get(provider, "DB_PORT")]'
```

Output:

```text
[some("9000"), some("5432")]
```

`config_standard` delegates to the existing provider using fixed indices and
precedence: overrides > explicit arguments > environment > `.env`. Its
two-argument form uses optional `.env`; a third explicit path is required.
Construction remains atomic and immutable, and returns the exact existing
provider Outcome. E13-5 and later R13 slices remain gated.
