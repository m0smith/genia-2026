# R15 — Validated Value Modeling

Status: **Active — E15-0 contract approved (#726/#738); E15-1 delivered (issue #728)**

R15 extends the completed R9 Value Template / representation model into a
more practical validated-value toolset. Delivered APIs remain
**Experimental**. See `docs/design/r15-validated-value-modeling-contract.md`
for the full approved release boundary and `GENIA_STATE.md` for final
implemented truth.

## E15-1 — Inert inspectable Template descriptions

Run:

```bash
genia -c 'Person = exact_shape({name: refinement((x) -> x != ""), age: refinement((x) -> x >= 0)})
[Person({name: "Ada", age: 3}), template_description(Person)]'
```

Output:

```text
[some({name: "Ada", age: 3}), some({kind: exact_shape, fields: {name: {kind: refinement}, age: {kind: refinement}}})]
```

`refinement(predicate)`, `open_shape(fields)`, and `exact_shape(fields)` are
curried one-argument Template builders with the same matching behavior as
the existing `refinement_match`/`open_shape_match`/`exact_shape_match`
helpers. Templates they build — and Templates `json_schema` compiles — carry
an inert, host-independent description that `template_description(template)`
returns as `some(description)`. Every other callable Template, including
arbitrary callables and named patterns declared with
`pattern Name(value) = ...`, remains fully valid but opaque and returns
`none("opaque-template")`.

Construction and inspection perform no effects: no user-data validation
runs, no predicate is executed, and no config/lifecycle/IO/import-time
activation occurs. Descriptions never affect callable identity, equality,
matching, dispatch, or `@?`/`@!`/`&` original-subject semantics.

E15-1 adds no defaults, diagnostics accumulation, schema generation,
structural alternatives, recursion, or new parser/Core IR surface — those
remain later R15 slices (#729 through #736).
