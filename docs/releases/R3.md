# R3 — Native Test Expansion Wave 1

Status: Complete. See `docs/strategy/release-roadmap.md` for full scope.

Theme: grow native test coverage over Genia-facing behavior without touching
parser/IR/host internals.

## What to run

R3's headline capability is `@test "description"` annotation-driven test
discovery (issue #458) — an alternative to R2's `test(name, body)` call form
where `@test`-annotated zero-argument functions are discovered and run
automatically in `genia test` mode.

```genia
add(x, y) = x + y

@test "add combines two numbers"
add_basic() = assert_eq(add(2, 3), 5)

@test "add is commutative"
add_commutative() = assert_eq(add(2, 3), add(3, 2))
```

Run it:

```bash
genia test path/to/this-file.genia
```

Output:

```text
total=2 passed=2 failed=0 errored=0
PASS add_basic
PASS add_commutative
total=2 passed=2 failed=0 errored=0
```

The `@test` annotation carries the human-readable description; the function
name becomes the test identifier in the report. `@test`-annotated functions
are discovered after any legacy `test(name, body)` registrations in the same
file and run through the same native test kernel — the two forms compose in
one file.

A larger native-test example covering the R1 validated-pipeline surface
