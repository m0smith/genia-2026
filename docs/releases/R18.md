# R18 — Portable Value Equality

Status: **Complete — E18-0 through E18-7 (#790–#797) delivered. The skeptical
release truth audit recorded a PASS verdict.**

R18 makes Genia's equality relation an explicit portable contract instead of a
delegation to the host language. Before R18 the Python reference host answered
`==` with Python's own equality, which meant `true == 1` was true, two
equal-content maps were unequal, two equal byte values were unequal, and a
protected carrier could be used to test whether two secrets matched.

`GENIA_STATE.md` remains final authority. The approved boundary is recorded in
`docs/design/r18-portable-value-equality-contract.md`.

## One relation

Genia has exactly one semantic equality relation. `==` denotes it and `!=` is
exactly its logical negation.

For the same two operands, all of these answer identically:

- `==` and `!=`
- literal pattern matching
- repeated pattern bindings
- `assert_eq`
- the meta-circular evaluator's `==` and `!=`
- map lookup, presence, insertion, replacement, removal, and duplicate-key detection
- Sheet column-name identity
- recursive List, Pair, Outcome, and represented-value comparison, and map equality

No surface consults host-language equality or a host container's key rules to
answer a semantic sameness question.

## Four families

**Structural values** compare recursively by named semantic contents: booleans,
integers, floats, strings, symbols, Lists, Pairs, `some`/`none`/`err` Outcomes,
maps, represented values, RNG states, Format values, byte values, ZIP entries,
and Sheets.

**Identity-bearing runtime values** compare only by logical runtime entity
identity. Equality never dereferences a Ref, inspects a Cell or Process, advances
a Seq or Flow, reads a provider's configuration or a module's exports, or invokes
a callable or matcher.

**Opaque semantic tokens** compare by three hidden identities — domain,
provenance, and semantic — established at mint time and read as data. No issuer
is contacted and no token-supplied comparator is consulted.

**Protected carriers** compare by carrier identity only.

## Numeric equality

Booleans are a distinct semantic kind and never compare equal to numbers:

```genia
[true == 1, false == 0, 1 == 1.0, 1 == 1.5, 0.0 == -0.0]
```

```text
[false, false, true, false, true]
```

An integer equals a float exactly when the float is finite, integral, and denotes
the same mathematical integer. The comparison is exact: a host must not decide it
by converting an arbitrary-precision integer to a float. Matching infinities are
equal, opposite infinities are not, and NaN is unequal to everything including
itself — a non-reflexivity that propagates through structural containers, so
`[nan] == [nan]` is false.

R17 arbitrary-precision integer semantics are unchanged.

## Map equality and keys

Map equality is equality of mappings, not of insertion history:

```genia
a = map_put(map_put(map_new(), "x", 1), "y", 2)
b = map_put(map_put(map_new(), "y", 2), "x", 1)
[a == b, map_keys(a), map_keys(b)]
```

```text
[true, ["x", "y"], ["y", "x"]]
```

Equal-content maps are equal even though their iteration orders differ. **Map
iteration order remains exactly the R17 contract and is a separate observable
from equality.** R18 changed which keys collide, never how order is maintained.

For legal keys, key identity is exactly `==`, so `true` and `1` are different
keys while `1` and `1.0` are one key:

```genia
map_count(map_put(map_put(map_new(), true, "bool"), 1, "int"))
```

```text
2
```

Legal keys are booleans, integers, non-NaN floats including infinities, strings,
symbols, and recursively legal Pairs, Lists, and represented values. Every legal
key satisfies `k == k`, so NaN — and any otherwise-legal key containing NaN at
any depth — is rejected, on every map operation rather than only on insertion.

Sheet column names use the same legal family and the same identity relation.

## Protected data is a security boundary

Protected equality observes carrier identity only. A carrier equals itself and
any alias of the same carrier; two independently acquired carriers are unequal
even when they share a provider and purpose and carry equal payloads.

Ordinary equality never compares protected payloads, so it cannot be used to test
whether two secrets match. Payload comparison requires the existing explicit
authorized declassification boundary first.

That non-interference holds through `==`, `!=`, recursive structural comparison at
any depth, Lists, Pairs, Outcomes, maps, map keys, patterns, assertions, hashing,
serialization, rendering, and rejection diagnostics. The equality result may
reveal carrier identity; it must never reveal payload equality.

The carrier type itself defines no host equality, so an internal host comparison
cannot reopen the oracle either.

## Conformance evidence

R18 ships **24 shared cases** under `spec/eval/` and `spec/error/`, covering every
equality family reachable from Genia source: numeric, structural, map equality
and keys, identity-bearing values, protected carriers, literal patterns,
duplicate bindings, and assertions. They are verified both in-process and through
the R16 generic host protocol, with zero cases reported `unsupported`.

The cases are written to detect the partial implementations most likely in
practice: reusing host `==`, reusing a host hash map's key rules, and
implementing `==` while leaving patterns and assertions on host equality.

`spec/eval/r18-conformance-cross-family-summary.yaml` compares a representative
value of every family against an equal value and a near miss in one program, so a
single failing index names the broken family.

## What R18 did not do

- **No C++ host was implemented.** Python remains the reference and only
  production host.
- **`==` is not user-overloadable.** No function, Template, matcher, provider, or
  future open-function mechanism can supply, replace, or intercept it. Programs
  may define ordinary predicates for approximate or domain-specific equivalence,
  but those cannot redefine `==`, literal-pattern equality, duplicate-binding
  consistency, or map-key identity.
- **No token-domain syntax, minting API, or token value was added.** Opaque
  semantic tokens are a contract and design family with no source-level surface:
  no token can be created or observed from Genia source in R18. The family is
  specified so a future built-in or user-defined token domain can participate by
  establishing three immutable identities at mint time — never by registering
  comparator code.
- **No storage `Revision` was implemented.** A `Revision` is a motivating future
  example of the opaque-token family, not something this release builds.
- **No map-order redesign.** R17's iteration contract is untouched.
- **No approximate equality, ordering, public hashing, or deep-diff diagnostics.**
- **No new public function, builtin, operator, syntax, capability, or Core IR
  node.** R18 changed evaluator and runtime semantics only.

R19 owns Unicode, float-display, and diagnostic hardening; R18 did not redesign
diagnostic text.

## Skeptical release audit

The E18-7 audit checked the approved contract, every R18 implementation path, all
24 shared cases, adversarial numeric and key edge cases, map equality and key
equivalence, legal-key rejection, protected-data non-interference, identity-bearing
behavior, the opaque-token design boundary, literal patterns, duplicate bindings,
`assert_eq`, representations, Outcomes, Sheets, callable and runtime values, host
leakage, documentation truth, R17 non-regression, R16 conformance integration, the
R20 open-functions boundary, and future C++ implementability.

Three checks were decisive rather than confirmatory:

- **Host leakage.** The relation's unclassified terminal was instrumented and the
  entire suite re-run — 4202 tests and 668 shared cases. It was reached 4 times,
  all by the deliberate test fixture that exists to prove the terminal never
  consults host `__eq__`. No value reachable from Genia source lands there.
- **Protected non-interference.** 29 observables were probed adversarially, each
  comparing an equal-payload carrier pair against a different-payload pair —
  equality, inequality, eleven container shapes, host equality, display, debug,
  hashing, map-key and Sheet-column rejection messages, JSON encoding, and
  arbitrary misuse error text. No observable can distinguish the pairs.
- **Legal-key family.** The documented family was checked against the
  implementation across 26 value families; all nine documented-legal families are
  accepted and all seventeen documented-illegal families are rejected.

**Verdict: PASS.**
