# R12 — Retrieval & Grounding

Status: **Active — E12-1 through E12-3 delivered**

E12-1 adds Experimental portable document/chunk/provenance behavior through one
ordinary `chunk/2` call. It validates a closed document and one list of spans,
slices the original text in Unicode code points, and owns exact source metadata.
It makes no provider call and adds no embedding, index, retrieval, reranking,
grounding, model, credential, or citation behavior.

Run:

```bash
genia -c 'doc = {id: "doc-1", text: "A😀éZ", meta: represent("json", {source: "fixture"})}
chunk((_text) -> [{offset: 1, length: 2}], doc) |> unwrap_or([]) |> map((item) -> [item.text, item.source])'
```

Output:

```text
[["😀é", {doc_id: "doc-1", offset: 1, length: 2}]]
```

The chunker supplies only exact `{offset, length}` spans. `chunk/2` constructs
text, document identity, source, and metadata from the validated original
document, preserving returned order and allowing overlap/repetition. A valid
empty span list returns `some([])`; the first malformed or out-of-bounds span
returns indexed `chunk-invalid`.

## E12-2 — explicit chunk/query embedding

E12-2 adds Experimental `embed/4`. One explicitly injected opaque fixture
capability returns an ordinary callable accepting exact chunk or query variants.
Successful output preserves the exact input identity and validates a nonempty
finite vector, exact dimensions, and the configured compatibility space. It
uses R10 `quote(embed_call)` authority immediately before one deterministic
offline attempt and never hides query embedding inside retrieval.

Run the focused executable proof:

```bash
uv run pytest -q tests/unit/test_r12_embedding_fixture.py::test_query_embedding_preserves_text_and_attempts_once tests/unit/test_r12_embedding_fixture.py::test_chunk_embedding_preserves_exact_chunk_and_metadata_identity
```

Output:

```text
..                                                                       [100%]
2 passed in 0.10s
```

The fixture is Python-host-only, explicit, non-ambient, and not constructible
from ordinary source. It has no network, clock, randomness, environment,
filesystem, or sleep dependency. E12-2 adds no retrieval, reranking,
grounding, implicit query embedding, persistence, or provider registry.

## E12-3 — indexing and an opaque handle

E12-3 adds Experimental `index/4`. Its ordinary callable validates a nonempty
embedded corpus and exact shared dimensions/space before declassifying through
R10 `quote(index_call)`. One deterministic offline attempt returns only an
opaque handle rendered `<index-handle>`.

Run the focused executable proof:

```bash
uv run pytest -q tests/unit/test_r12_indexing_fixture.py::test_compatible_corpus_attempts_once_and_returns_only_opaque_handle tests/unit/test_r12_indexing_fixture.py::test_local_embedding_failures_precede_declassification
```

Output:

```text
......                                                                   [100%]
6 passed in 0.13s
```

The handle cannot be source-constructed, inspected, compared, keyed, copied,
serialized, or persisted. Its backend reference, compatibility identity,
space, and dimensions remain host-private. This deterministic fixture adds no
networking, vector-database ownership, public index storage, or retrieval.

R12 remains active. E12-4 and later behavior is not implemented by this slice.
