# R10 — Configuration & Secrets

Status: **Active — E10-1 provider acquisition and E10-2 defaults/conversion validation implemented**

E10-1 adds explicit immutable configuration providers and exact raw-string lookup. E10-2 adds missing-only lazy defaults and proves explicit Outcome conversion plus callable Template validation. Later protected-secret, sink-safety, declassification, cross-mode, and proving-case slices are not implemented by this page.

Run:

```bash
genia -c 'pattern Positive(value) = refinement_match((n) -> n > 0, value)
provider = config_provider([{kind: quote(values), values: {PORT: "8080", EMPTY: ""}}]) |> unwrap_or(none)
[
  config_get_or(provider, "PORT", () -> "3000") |> parse_int |> Positive,
  config_get_or(provider, "EMPTY", () -> "3000"),
  config_get_or(provider, "MISSING", () -> "3000") |> parse_int |> Positive
]'
```

Output:

```text
[some(8080), some(""), some(3000)]
```

`quote(values)` is explicit descriptor data; it does not add a global `values` name. Sources are ordered highest to lowest precedence, copied at construction, and never refreshed during lookup. The Python reference host also supports `{kind: quote(environment)}` as a construction-time process-environment snapshot. Normalized failures omit configuration keys, raw values, source contents, and host exception detail.

`config_get_or` calls its zero-argument default once only for missing lookup. Empty and found values bypass it. Conversion is explicit (`parse_int`) and validation is the existing callable Template (`Positive`); neither acquisition operation coerces values.
