# R27 — C++ Flow and Pipe Mode

Status: **Complete (E27-0 through E27-6).** `GENIA_STATE.md` remains final
authority for implemented behavior. R27 was planned as "C++ Flow, Pipe Mode, and
HTTP Serving"; the HTTP server and outbound HTTP were deferred (below), so the
release is named for what it delivered.

R27 extends the bounded C++ host with two independently gated portable
capabilities. Each claim is exactly the shared cases that carry the matching
`requires:` gate, and every one of them passes.

| Capability | C++ declaration | Gated shared cases | Portable observation |
| --- | --- | --- | --- |
| `flow_phase_1` | `supported` | 37 | lazy, pull-based, single-use Flow: `stdin`/list `lines`, `evolve`, `map`/`filter`/`take`/`drop`/`scan`/`keep_some`/`each`, `collect`/`run`/`reduce`; bounded demand; the single-use error and its pipeline-stage wrapper |
| `cli_pipe_mode` | `supported` | 16 | `genia -p '<stage expr>'` over piped stdin: `stdin \|> lines \|> <expr>` with automatic final consumption, `main` bypass, explicit `stdin`/`run` rejection, non-Flow result rejection, per-item and reducer guidance, `argv()` in pipe mode |

## Deferred, not delivered

| Surface | Decision | Why |
| --- | --- | --- |
| HTTP server (`http_server`) | deferred, E27-3 (#1041) | Python-host-only blocking bridge; no shared evidence route and the E16-1 protocol cannot drive a server; the C++ host lacks `import`, annotations, a `serve` mode and sockets; listener authority undecided. `docs/analysis/r27-http-server-decision.md` |
| Outbound HTTP (`http_outbound_transport`) | deferred, E27-4 (#1043) | no Genia surface of its own; host-minted R10 declassification authority; runner fixture plumbing missing; the C++ host lacks `import`, protected values and lifecycle scopes. `docs/analysis/r27-outbound-http-decision.md` |

Both remain tracked `KNOWN_GAP` entries in `spec/known_host_gaps.json`. R27 makes
no claim about either in C++.

## Small runnable examples

### Flow phase 1

Shared flow case `spec/flow/evolve-init-f-integer-progression.yaml`, passing in
both the Python reference host and the bounded C++ host:

```genia
inc(n) -> n + 1
evolve(0, inc) |> take(5) |> collect
-- [0, 1, 2, 3, 4]
```

`take(5)` bounds the unbounded `evolve` Flow; the source is never asked for more
than five items.

### Pipe mode

Shared CLI case `spec/cli/pipe_mode_map_parse_int.yaml`:

```text
$ printf '10\n20\n' | genia -p 'map(parse_int) |> keep_some |> each(print)'
10
20
```

## Not claimed

- The rest of `spec/flow/*` in C++: `tee`/`merge`/`zip`, `rules`/`refine`/`step_*`,
  `rand_flow`, list-form `scan`, `reduce` with an Option accumulator, Flow display.
- Pipe cases that need configuration views, model fixtures, Templates, or
  `json_compat` (`r10`/`r11`/`r13`/`r15-cross-mode-pipe`,
  `validated_record_pipeline_killer_workflow`, the `collect_validated` boundary
  case): Python-host-only.
- Trailing script arguments after `-p <expr>`; `argv()` outside pipe mode.
- Non-ASCII `upper`/`trim`/`parse_int`; stdin containing a carriage return.
- A pipeline inside call arguments (`f(a |> b)`), a C++ parser gap.
- Python/C++ feature parity. No language behavior changed in this release; Python
  semantics are unchanged.
