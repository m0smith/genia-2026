## Release R21 — Numeric Source and Portable Representation

**Status: Planned, not active.**

Theme:

> Freeze what numeric source means at parse/lowering/Core-IR boundaries before changing runtime mathematics.

Candidate scope:

- classify integer and Decimal source forms semantically
- preserve unary sign lowering
- parse Decimal source lexically/base-10 without binary-float transit
- keep the portable Core IR node family unchanged
- lower numeric literals through tagged `IrLiteral.value` payloads
- canonicalize Integer `digits` and Decimal `coefficient`/`exponent` payloads
- preserve `/` as `IrBinary(op=SLASH)`
- add shared parse/IR evidence for equivalent spellings, exponent forms, huge integers, and unary negatives
- update implemented-truth docs only for behavior actually merged

Explicit non-goals:

- Decimal/Rational/Float64 runtime arithmetic
- numeric conversion builtins
- cross-kind equality changes
- JSON numeric transport
- canonical numeric rendering/formatting
- C++ implementation

Critical acceptance criterion:

- A conforming host can classify and lower numeric source into the same portable tagged Core IR without consulting Python numeric behavior.

Delivery rule:

- R21 may use multiple independently mergeable PRs against current `main`; no long-lived release implementation branch is required.

## Release R22 — Exact Numeric Runtime

**Status: Planned, not active.** R22 consumes R21's source/Core-IR contract.

Theme:

> Make Genia's numeric value model exact by default, with Float64 explicit.

Candidate scope:

- canonical Decimal runtime values
- reduced Rational runtime values with denominator-one collapse to Integer
- explicit Float64 runtime values
- direct Decimal literal materialization without host-float transit
- `rational`, `float64`, and `exact` conversions
- exact-family `+`, `-`, `*`, `/`, and `%`
- explicit Float64 arithmetic and rejection of mixed exact/Float64 arithmetic without conversion
- mathematical comparison/equality across Integer/Decimal/Rational
- exact-dyadic Float64 comparison bridge without rounding the exact operand
- R18 map-key/legal-key reconciliation, including NaN non-reflexivity
- deterministic numeric misuse and normalized resource-limit behavior
- focused compatibility hardening for existing numeric consumers as separate mergeable slices where required

Explicit non-goals:

- generic JSON transport policy
- display/debug spelling
- numeric field-format presentation
- Float64 source suffix/raw-bit syntax
- Rational literal syntax
- transcendental APIs or ambient precision context
- C++ implementation

Critical acceptance criterion:

- Equivalent numeric computations and comparisons produce the same mathematical values and portable failures across conforming hosts independent of host integer/float/library defaults.

## Release R23 — Numeric Representation and Interchange

**Status: Planned, not active.** R23 consumes R21 and R22.

Theme:

> Make numeric values cross textual and JSON boundaries without silently reintroducing host binary-float semantics.

Candidate scope:

- canonical Decimal display/debug rendering
- canonical Rational rendering
- explicit constructor-shaped Float64 rendering
- REPL/CLI/result rendering consistency
- existing field-format integration for Decimal/Rational/Float64
- retain R9 generic JSON safe-integer policy
- define and implement `stable_json_decimal`
- generic JSON encode/decode for the approved numeric domains
- lexical fraction/exponent JSON decode directly to exact Decimal
- ensure JSON never constructs Rational directly
- reject non-finite Float64 at the generic JSON boundary
- reconcile legacy JSON compatibility entry points so they do not preserve a contradictory host-float model
- preserve R19 diagnostic normalization

Explicit non-goals:

- arbitrary-precision generic JSON-number transport
- new JSON dialect
- new numeric syntax
- representation-facet redesign unrelated to numeric transport
- C++ implementation

Critical acceptance criterion:

- Display/debug, formatting, and JSON boundaries preserve the approved numeric distinctions and never implicitly route Decimal semantics through host binary floating point.

## Release R24 — C++ Minimal Conforming Host

**Status: Planned, not active.** R24 depends on completed and audited R16-R23 foundations. Issue #814 is the pre-flight gate under the new numbering.

Theme:

> Bring up the smallest useful C++ host over the frozen portable Core IR boundary in `m0smith/genia-cpp`.

Repository boundary:

- all C++ production implementation introduced by R24 belongs in `m0smith/genia-cpp`
- `genia-2026` remains authoritative for contract/spec/conformance truth
- the C++ repository records the exact `genia-2026` contract revision it implements
- if implementation exposes ambiguous portable behavior, stop host-side guessing, clarify contract/spec upstream, then resume

Candidate scope:

- choose/document C++ build, dependency, test, formatting, and lint toolchain
- implement current documented lexer/parser surface and normalized parse adapter operation
- lower into only the frozen portable Core IR node/pattern families before host-local optimization
- implement capability-light Core IR evaluation for literals, collections, Outcomes, operators, pipelines, patterns/cases, lambdas, assignments, function definitions, and R20 open-function dispatch within the declared capability set
- implement R17 integer/ordered-map semantics, R18 equality/key semantics, R19 Unicode/diagnostic semantics, R20 open functions, and completed R21-R23 exact-numeric semantics
- implement file mode, `-c` command mode, raw `argv()`, prelude loading/autoload, and required `help(name)` surface
- publish capability-aware R16 conformance evidence with exact passed/unsupported/failure counts

Explicit non-goals:

- `-p`/pipe mode or REPL
- Flow phase 1
- refs, cells, processes, actors, or scheduler semantics
- HTTP serving/outbound HTTP
- resource IO, model/embedding fixtures, provider adapters, or allowlisted host interop
- defining Genia semantics from C++ implementation choices

Critical acceptance criterion:

- A Genia program within the declared minimal capability set has the same normalized parse/Core-IR shape and observable result under C++ and Python for every applicable shared case, tied to an exact authoritative contract revision.
