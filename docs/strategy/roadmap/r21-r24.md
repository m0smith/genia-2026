# R21–R24 — Exact Numeric Model and Minimal C++ Host

Status: Planned roadmap detail — non-authoritative. `GENIA_STATE.md` remains final authority for implemented behavior.

Planning issue #845 decomposes exact numeric work into three numbered releases before the first real C++ host. PR #839 remains historical design/test evidence and is not the implementation vehicle.

## Release R21 — Numeric Source and Portable Representation

**Status: Complete.** E21-1 (numeric source classification, #853), E21-2
(tagged portable `IrLiteral` payloads, #854), E21-3 (cross-surface
conformance hardening, #855), E21-4 (documentation truth sync, #856), and
E21-5 (skeptical release audit, #857) are all merged to `main`. The
skeptical release truth audit recorded PASS in
`docs/analysis/r21-release-truth-audit.md`. See `GENIA_STATE.md` sections
9.21–9.22 and `docs/releases/R21.md` for landed implemented behavior.

Theme: freeze numeric source classification and portable Core IR representation before changing runtime mathematics.

Candidate scope: semantic Integer/Decimal source classification; lexical/base-10 Decimal parsing; unary sign remains unary; tagged `IrLiteral.value` payloads using the existing Core IR node family; canonical Integer digits and Decimal coefficient/exponent; shared parse/IR evidence.

Explicit non-goals: runtime Decimal/Rational/Float64 arithmetic, conversions, equality changes, JSON, rendering/formatting, or C++ implementation.

Critical acceptance criterion: a conforming host can classify and lower numeric source to identical portable tagged Core IR without host numeric defaults.

## Release R22 — Exact Numeric Runtime

**Status: Complete.** E22-1 (exact Decimal runtime materialization,
#887), E22-2 (Rational runtime value, #888), E22-3 (exact-family
`+`/`-`/`*`, #889), E22-4 (exact division and floor remainder, #890),
E22-5 (explicit Float64 value and conversions, #891), E22-6 (Float64
arithmetic and mixed-domain rejection, #892), E22-7 (mathematical
comparison, equality, and R18 map-key reconciliation, #893), E22-8
(numeric misuse, resource limits, and diagnostic normalization, #894),
E22-9 (cross-surface conformance and compatibility hardening, #895),
E22-10 (documentation and release-example truth synchronization, #896),
and E22-11 (skeptical release audit, #897) are all merged to `main`. The
skeptical release truth audit recorded PASS in
`docs/analysis/r22-release-truth-audit.md`. See `GENIA_STATE.md` sections
9.23–9.31 and `docs/releases/R22.md` for landed implemented behavior.

Theme: make Genia's numeric value model exact by default with Float64 explicit.

Candidate scope: canonical Decimal and Rational runtime values; explicit Float64; exact-family arithmetic/division/remainder; `rational`, `float64`, and `exact`; mixed exact/Float64 rejection without explicit conversion; mathematical comparison/equality; R18 key reconciliation; deterministic numeric misuse/resource-limit behavior; focused compatibility hardening as separate slices when required.

Explicit non-goals: JSON transport, display/debug spelling, field-format presentation, new literal syntax, transcendentals/ambient precision, or C++ implementation.

Critical acceptance criterion: numeric computations/comparisons are host-independent and mathematically consistent with the approved model.

## Release R23 — Numeric Representation and Interchange

**Status: Complete.** E23-1 (canonical numeric rendering, #911), E23-2
(field-format-spec integration, #913), E23-3 (strict generic JSON
boundary for Integer/Decimal, #915), E23-4 (strict generic JSON boundary
for Rational/Float64, #921), E23-5 (compatibility JSON reconciliation,
#923), E23-6 (diagnostics normalization sweep + docs/release truth sync,
#925), E23-7 (release truth audit, #931 -- FAIL, one genuine
`GeniaRational` type-name leak found), E23-8 (repair, #933), E23-9
(second release truth audit, #935 -- FAIL, a doc-sync gap found), E23-10
(repair, #937), and E23-11 (third, independent skeptical release truth
audit, #939 -- **PASS**) are all merged to `main`. See
`docs/design/r23-numeric-representation-interchange-contract.md`
(approved contract), `docs/analysis/r23-release-truth-audit.md` (the
full three-pass audit trail), and `GENIA_STATE.md` sections 9.32-9.37 for
landed behavior.

Theme: make numeric values cross textual and JSON boundaries without reintroducing implicit host binary-float semantics.

Candidate scope: canonical Decimal/Rational/Float64 rendering; REPL/CLI consistency; existing numeric format-spec integration; R9 generic JSON limits; `stable_json_decimal`; lexical JSON Decimal decode; Rational/Float64 JSON rules; legacy JSON compatibility reconciliation; R19 diagnostic normalization.

Explicit non-goals: arbitrary-precision generic JSON transport, a new JSON dialect, new numeric syntax, unrelated representation redesign, or C++ implementation.

Critical acceptance criterion: rendering/formatting/JSON preserve numeric distinctions and never implicitly route Decimal semantics through host binary floating point.

## Release R24 — C++ Minimal Conforming Host

**Status: Planned, not active. Pre-flight gate GO (2026-09-19).** Depends
on completed and audited R16–R23 foundations, which this refresh
re-verified. Issue #814 (`R24-0`) is the pre-flight gate under the new
numbering, and is closed/completed. The renamed pre-flight document
(`docs/design/r24-cpp-host-preflight.md`) and its four mandatory entry
artifacts (`docs/design/r24/capability-floor.json`,
`docs/design/r24/bootstrap-cases.json`,
`docs/design/r24/native-primitive-inventory.md`,
`docs/design/r24/dependency-toolchain-policy.md`) are pinned. This GO
authorizes drafting the E24 implementation ticket sequence
(`docs/strategy/roadmap/e24-issue-sequence.md`); it does not itself
constitute or authorize C++ semantic implementation.

Theme: bring up the smallest useful C++ host over the frozen portable Core IR boundary in `m0smith/genia-cpp`.

Candidate scope: C++ toolchain; parser and normalized parse adapter; portable Core IR lowering; capability-light Core IR evaluation; R17 integers/maps; R18 equality/keys; R19 Unicode/diagnostics; R20 open functions; completed R21-R23 numeric semantics; file mode, `-c`, argv, prelude/autoload/help; R16 capability-aware conformance evidence.

Explicit non-goals: pipe/REPL, Flow, refs/cells/processes/actors, HTTP, resource IO, model/provider interop, or defining Genia semantics from C++ choices.

Critical acceptance criterion: every applicable shared case in the declared minimal capability set matches the Python reference host under an exact authoritative contract revision.
