# R25–R29 — C++ Host Expansion, MCP, and Sheet Record Pipelines

Status: Planned roadmap detail — non-authoritative. `GENIA_STATE.md` remains final authority for implemented behavior.

These releases follow R24 — C++ Minimal Conforming Host. R25-R27 complete the planned C++ expansion arc, R28 is the Genia MCP Server, and R29 returns directly to the validated-data-pipeline killer workflow with Sheet record pipelines.

## Release R25 — C++ Stateful Runtime and Concurrency

**Status: Planned, not active.** R25 depends on R24. Any currently Python-host-only stateful surface requires an explicit portability-promotion contract before its C++ implementation is treated as shared behavior.

Theme:

> Add stateful capabilities only after C++ ownership, cycles, cleanup, and concurrency are explicit.

Candidate scope retains the former R22 plan: C++ ownership/lifetime strategy for values, closures, environments, refs, cells, process handles, and cycles; promoted observable contracts for refs/cells/processes; deterministic concurrency/lifecycle stress tests; evidence-based capability claims; upstream ambiguity resolution rather than Python imitation.

Explicit non-goals remain: language-level scheduler, async/await, supervision tree, distributed actors, HTTP/resource IO, or treating C++ ownership choices as Genia semantics.

## Release R26 — C++ REPL and Data Bridges

**Status: Planned, not active.** R26 depends on R24. Each Python-host-only bridge requires a portability-promotion contract before implementation.

Theme:

> Extend the minimal host with interactive evaluation and deterministic data boundaries.

Candidate scope retains the former R23 plan: REPL parity; promoted bytes/UTF-8, strict JSON, and ZIP boundaries; duplicate-key rejection, JSON numeric limits, Unicode validation, nesting caps, deterministic output, normalized Outcomes/errors; capability-tagged shared evidence.

Explicit non-goals remain: pipe/Flow, HTTP serving, resource IO, allowlisted host interop, debugger stdio, or loosening portable behavior to match library defaults.

## Release R27 — C++ Flow, Pipe Mode, and HTTP Serving

**Status: Planned, not active.** R27 depends on R24 and any R25/R26 behavior actually required by its approved designs.

Theme:

> Complete the largest remaining portable runtime surfaces without turning C++ internals into Genia semantics.

Candidate scope retains the former R24 plan: lazy pull-based single-use Flow phase 1; `-p`/pipe mode over Flow; explicitly promoted HTTP/server behavior; current R8 lifecycle/server semantics; capability-aware shared evidence; final differential audit with honest unsupported classifications.

Explicit non-goals remain: unsupported model/embedding/provider/resource capabilities, debugger stdio, or claiming complete host parity from only capability-compatible passes.

## Release R28 — Genia MCP Server

**Status: Planned, not active.** Integration infrastructure; MCP adapts implemented Genia behavior and must not define a second semantics path.

Theme:

> Publish Genia as a small, governed Model Context Protocol server so MCP-capable hosts can inspect and invoke Genia through explicit structured boundaries.

Planned v1 surface:

- `genia_parse` over existing parse/normalization behavior
- `genia_run` over explicitly approved host execution paths
- `genia_capabilities` for stable adapter/host capability reporting
- stdio as required local transport; Streamable HTTP only if the contract/threat-model gate approves it
- structured separation of returned value, emitted output, diagnostics, protocol errors, parse/runtime failures, and policy rejection
- timeout/cancellation/result-size policy
- protected-value redaction and no ambient filesystem/environment/secret authority
- official MCP client/SDK integration tests and direct-host parity tests
- one runnable Outcome-aware validated-data-pipeline demo

Existing planning epic #700 and issues #701-#707 are the R28/E28-* work items after renumbering under #845.

Explicit non-goals: MCP client behavior inside Genia, agent orchestration, autonomous tool selection, filesystem workspace server, shell execution, new Genia syntax/Core IR solely for MCP, or a production multi-tenant sandbox.

## Release R29 — Sheet Record Pipelines

**Status: Planned, not active.** Focused killer-workflow release after the C++ host arc and MCP integration release.

Theme:

> Make immutable Sheets explicit sources and destinations for AWK-like, Outcome-aware record pipelines without making Sheets implicitly Seq-compatible or introducing an AWK execution mode.

Candidate scope retains the former R25 plan: explicit Sheet-to-record-sequence boundary; row/column identity and order; bounded lazy behavior/finalization; ordinary per-record context; R14 repeated element scopes; ordinary `scan`/`reduce` state; schema-preserving versus explicit schema-changing operations; Outcome/protected-value preservation; shared eval/flow/error evidence.

Explicit non-goals remain: `$0`/`$1`/`NR`/`NF` syntax, AWK execution mode, implicit Sheet Seq compatibility, automatic coercion, dataframe/query DSLs, joins/grouping/windowing in this release, mutable row globals, or a second Outcome/Template/validation model.
