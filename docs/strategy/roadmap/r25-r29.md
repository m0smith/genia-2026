# R25–R29 — C++ Host Expansion, MCP, and Sheet Record Pipelines

Status: Planned roadmap detail — non-authoritative. `GENIA_STATE.md` remains final authority for implemented behavior.

These releases retain the prior C++ expansion, MCP, and Sheet plans under the post-#845 numbering.

## Release R25 — C++ Stateful Runtime and Concurrency

**Status: Complete through E25-5; ordered PR stack merged and audited.** Depends on R24.

Theme: add stateful C++ capabilities only after ownership, cycles, cleanup, and concurrency observations are explicit.

Delivered scope: C++ ownership/lifetime strategy; portability promotion for refs/cells/process observations; threading/mailbox/failure/cleanup mapping; deterministic stress/race/lifecycle tests; evidence-based capability claims. See `docs/releases/R25.md` for the bounded floor and final evidence.

Explicit non-goals: language scheduler, async/await, supervision tree, distributed actors, HTTP, or resource IO.

Actor and ActorRef are completely excluded from R25 and belong to R38. R25
adds no general supervision/restart policy, mailbox capacity/backpressure,
distributed messaging, events/pub-sub, or placement behavior. Its approved
sequence is E25-0 contract/evidence, E25-1 Ref, E25-2 Cell, E25-3 local
Process/mailbox, E25-4 cross-cutting hardening, and E25-5 release truth/audit.

## Release R26 — C++ REPL and Data Bridges

**Status: Complete through R26-1 and R26-2.** Depends on R24; bridge tracks were separately gated and are now merged.

Theme: extend the minimal host with interactive evaluation and deterministic data boundaries.

Scope was narrowed by the R26-0 pre-flight and the `docs/analysis/r26-release-size-preflight.md` architecture record:

- **R26-1 (REPL, issue #1023):** portable contract approved (`docs/design/r26-cpp-repl-contract.md`); scripted C++ sessions pass the three capability-gated shared CLI cases, and the parity gate reports `PARITY_OK`.
- **R26-2 (Bytes/UTF-8 and strict JSON, issue #1024):** completed Bytes/UTF-8 and the strict JSON boundary (`json_decode`/`json_encode`), inheriting the E24-3/E24-7 numeric codec path rather than re-deriving it. ZIP was removed from R26 entirely. Compatibility JSON (`json_parse`/`json_stringify`/`json_pretty`, `parse_jsonl_record`) was classified as not portable and remains Python-host-only by contract. `json_schema` stays out (Template runtime dependency).
- **`debugger_stdio` (issue #1025):** deferred, not part of R26.
- **ZIP:** deferred out of R26 entirely; roadmap home explicitly TBD, pending its own contract-first placement that reconciles the eager/Flow split and R35 resource authority.

Explicit non-goals: pipe/Flow and HTTP serving; ZIP (this release); Python/C++ feature-parity claims.

Current known C++ host gaps are grouped by release in
[`cpp-host-gap-burndown.md`](cpp-host-gap-burndown.md). That report is planning
guidance only and does not reopen completed R26 work without a new gate.

## Release R27 — C++ Flow and Pipe Mode

**Status: Complete (E27-0 through E27-6).** Originally planned as "C++ Flow, Pipe Mode, and HTTP Serving"; the HTTP work was deferred by E27-3 and E27-4 and the release is retitled to the scope it delivered. See `docs/releases/R27.md` for evidence and `docs/analysis/r27-release-truth-audit.md` for the audit.

Theme: complete the largest remaining portable runtime surfaces without turning C++ internals into Genia semantics.

Delivered, each against shared `requires:`-gated evidence:

- **E27-1 (#1035):** C++ Flow phase 1 (`flow_phase_1`): lazy, pull-based, single-use Flow.
- **E27-2 (#1038):** C++ `genia -p` pipe mode (`cli_pipe_mode`).
- **E27-5 (#1047):** hardening of both, with 21 Python-generated cases; `flow_phase_1` has 37 gated cases and `cli_pipe_mode` 16, all passing in C++.

Deferred, not partially claimed:

- **E27-3 (#1041):** the HTTP server. The surface is Python-host-only, no shared evidence route exists, and the C++ host lacks `import`, annotations, a `serve` mode and sockets. See `docs/analysis/r27-http-server-decision.md`.
- **E27-4 (#1043):** outbound HTTP. It has no Genia surface of its own, needs host-minted R10 declassification authority and runner fixture plumbing the shared protocol lacks, and the C++ host lacks `import`, protected values and lifecycle scopes. See `docs/analysis/r27-outbound-http-decision.md`.

Both stay tracked C++ gaps in `spec/known_host_gaps.json` under a later contract-first gate; the C++ gap burn-down report is [`cpp-host-gap-burndown.md`](cpp-host-gap-burndown.md). The release-size preflight (`docs/analysis/r27-release-size-preflight.md`) and contract reconciliation (`docs/analysis/r27-contract-evidence-reconciliation.md`) are planning records only.

## Release R28 — Genia MCP Server

**Status: Complete.** Epic #700 and issues #701-#707 delivered this release under E28-0 through E28-6: the contract and threat model (with Clarifications A1-A4 and amendment A5, the `2025-11-25` compatibility era), the native `mcp.genia` server with exactly `genia_capabilities`, `genia_parse`, and `genia_run` over local stdio on the Python reference host (E28-1 to E28-3), the checked-in `.mcp.json` client configuration and lifecycle (E28-4, PR #1080), the conformance and parity matrix (E28-5, PR #1081), and the demo, publishing documentation, and release audit (E28-6, PR #1082). Follow-up amendment A6 adds the fourth tool, `genia_language_profile`, as an MCP adapter affordance that teaches assistants Genia's pattern-matching and recursion model without changing language semantics. Authentic VS Code + GitHub Copilot acceptance **run 3 passed** (macOS) against the original three-tool surface; runs 1 and 2 failed and are preserved in `docs/mcp/acceptance/vscode-copilot-evidence.md` (run 1 at `initialize`, fixed by amendment A5; run 2 at `genia_run` on macOS, fixed by ledger R28-H47). See `docs/releases/R28.md`. Python remains the only MCP host; there is no C++ MCP implementation, no Streamable HTTP, and no MCP resources or prompts.

Theme: publish a small governed MCP server authored primarily in native Genia
so MCP-capable clients can inspect and invoke Genia without acquiring new
language semantics. Host code is a narrow capability boundary, not the MCP
application architecture.

Candidate scope: contract/threat model; native `mcp.genia` skeleton and
capabilities; parse/inspection; governed execution; local stdio; host-dependency
inventory; conformance/parity matrix; runnable demo and release truth audit.
The audit must move accidental host-side application logic into Genia and route
evidence-backed missing reusable Genia facilities through owned pre-flight and
normal roadmap placement. R28 does not implement C++ MCP support; the future
portability target is the same `mcp.genia` program over each host's minimal
capability boundary. Streamable HTTP is deferred from R28 v1.

The living findings ledger `docs/analysis/r28-host-dependency-inventory.md` is a
required input to every R28 phase and the final audit: each phase updates it when
it discovers, resolves, reclassifies, or promotes a host dependency or Genia gap.
Discovery alone creates no language-feature issue; entries are promoted only via
the normal issue → pre-flight → roadmap process, and the final audit dispositions
every open entry.

Release acceptance requires a checked-in, credential-free, portable MCP client
configuration (prefer repository-level `.mcp.json`; use `.vscode/mcp.json` only
if verified VS Code requirements demand it) and a reproducible VS Code/Copilot
development loop over the same local stdio `mcp.genia` server. The client must
discover exactly the three v1 tools, use parse feedback to repair invalid Genia
source, run the correction with value/stdout/stderr separation, and demonstrate
that program output cannot corrupt protocol framing or widen authority. Final
documentation must cover setup, discovery, enablement, verification, example
use, and troubleshooting. Post-release AI guidance should prefer this MCP for
appropriate Genia inspection/execution and audit any Python/shell bypasses as
evidence for the normal issue/pre-flight/roadmap gap process, not as automatic
language-feature authority.

R28 should also consider a canonical MCP-backed grounded-answering showcase,
provided it fits the approved contract and threat model: MCP-supplied context,
documents, or tool outputs enter Genia through an explicit governed boundary;
Genia then runs an Outcome-aware retrieval/grounding pipeline that preserves
source provenance, evidence shaping, and visible diagnostics before any LLM call.
This is planning guidance only: it does not add `rag_chat`, does not implement
MCP client behavior inside Genia, does not add an Ollama/Groq/RAG provider to
`model/4`, and must not be documented as implemented behavior before a future
R28 contract, tests, implementation, docs sync, and audit actually land.

Issue #1085 classifies the remaining R28 follow-up surface after amendment A6:
SICP artifacts are not R28 inputs; the existing language profile is complete for
the immediate pattern-matching/no-`if` guidance; structured maturity/gap
discovery is delivered by #1086 / amendment A7 as 12 static scoped profile
facts mapped to STATE; and the MCP-backed grounded-answering showcase is
tracked by #1087. Both child issues have their own pre-flight gate; A7
changes only MCP discovery metadata, and #1087 remains separate planning work. See
`docs/design/r28-follow-up-1085-classification-preflight.md`.

The #1087 follow-up delivered a narrow tested executable example only:
`examples/mcp/grounded_evidence.genia` runs through unchanged `genia_run`,
validates client-supplied document literals, chunks valid documents with
Experimental R12 `chunk/2`, and emits a stdout JSON evidence package with exact
provenance and indexed diagnostics. Provider-backed embedding, retrieval,
reranking, and generation are unavailable under the R28 execution profile and
are not part of it; answer generation stays with the MCP client. The example is
ordinary Python-reference-host MCP behavior, not a new tool, authority, builtin,
language surface, RAG feature, or C++ MCP claim. See
`docs/design/r28-follow-up-1087-grounded-showcase-preflight.md` and
`docs/design/r28-follow-up-1090-grounded-evidence-contract-design.md`.

Explicit non-goals: MCP client inside Genia, autonomous agent orchestration, arbitrary filesystem/shell authority, new syntax/Core IR, or a production multi-tenant sandbox.

## Release R29 — Sheet Record Pipelines

**Status: Planned, not active.** Focused killer-workflow release after the C++ host-parity arc and MCP integration release.

Theme: make immutable Sheets explicit sources and destinations for AWK-like, Outcome-aware record pipelines without implicit Sheet-to-Seq conversion or an AWK execution mode.

Candidate scope retains the prior plan: explicit Sheet-to-record boundary; deterministic row/column order and per-record context; bounded Flow behavior/finalization; R14 repeated element scopes; ordinary `scan`/`reduce` state; schema-preserving versus explicit schema-changing operations; Outcome/protected-value preservation; shared eval/flow/error evidence.

Explicit non-goals: `$0`/`$1`/`NR`/`NF` syntax, mutable row globals, implicit Sheet Seq compatibility, dataframe/query DSLs, joins/grouping/windowing, automatic coercion, or a second Outcome/Template/validation model.
