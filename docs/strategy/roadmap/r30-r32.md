# R30–R34 — Shaped Data, Relational Workflows, Data Boundaries, Tooling, and Performance

Status: Planned roadmap detail — non-authoritative. `GENIA_STATE.md` remains final authority for implemented behavior.

These releases are the former R26-R30 plan shifted after R21-R23 numeric work and R28 MCP were made explicit numbered releases. Their scope intent is unchanged.

## Release R30 — Sheet Shaped Computation

**Status: Planned, not active.** R30 depends on R29's explicit Sheet/record boundary and preserves immutable Sheet ownership.

Theme: make columns and other shaped values participate in predictable whole-value computation without mutable spreadsheet semantics or implicit Sheet-to-Seq conversion.

Candidate scope retains the former R26 plan: portable shape/rank observations, scalar lifting, deterministic shape-conformance diagnostics, an explicit column-expression boundary, whole-column derivation, narrow elemental lifting, Outcome preservation, and shared eval/error evidence.

## Release R31 — Relational Sheet Operations

**Status: Planned, not active.** R31 depends on R29 and may consume R30 shaped-computation semantics while keeping relational operations distinct from elemental shape operations.

Theme: add the small relational toolkit needed for practical validated-data workflows without creating a second SQL/dataframe language.

Candidate scope retains the former R27 plan: deterministic grouping, grouped summarization, ordering/sorting, explicit key joins, duplicate/unmatched/collision/output-order rules, explicit schema changes, and Outcome/protected-value preservation.

## Release R32 — Database Data Boundary

**Status: Planned, not active.** R32 builds on validated pipelines, configuration/secrets, lifecycle, Flow, Sheets, and relational foundations.

Theme: make databases ordinary explicit sources and sinks without an ORM or ambient connection state.

Candidate scope retains the former R28 plan: explicit parameterized queries, ordered result boundaries through existing Flow/Seq/Sheet machinery, explicit writes/transactions only as justified, R10/R13 credentials, R14 lifetime ownership, portable driver-failure normalization, deterministic column handling, explicit provider selection, and one end-to-end proving workflow.

## Release R33 — Developer Experience and Language Tooling

**Status: Planned, not active.** Tooling must derive from implemented parser/Core-IR/help/debugger truth and must not create editor-local semantics.

Theme: make ordinary Genia development pleasant enough that the language's semantic simplicity is visible in the editor.

Candidate scope retains the former R29 plan: canonical formatter, parser-derived diagnostics/source ranges, navigation/references/rename/hover/signatures, narrowly justified project bootstrap support, synchronized help/reference docs, and formatter/tooling regression evidence.

## Release R34 — Cross-Host Performance and Optimization Evidence

**Status: Planned, not active.** R34 follows the R24-R27 C++ host arc and should include R29-R31 data-workflow surfaces where both hosts claim the relevant capabilities.

Theme: measure what the second host actually buys Genia and optimize only where evidence identifies meaningful cost without changing portable semantics.

Candidate scope retains the former R30 plan: reproducible startup/parse/eval/pattern/Flow/Sheet/relational benchmarks; exact host/build/machine metadata; variance/warmup policy; allocation/copying/dispatch/boundary hotspot analysis; conformance-proven host-local optimizations; stable regression thresholds only where measurements justify them.
