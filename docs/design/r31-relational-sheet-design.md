## 1. Python reference host

**Placement (P).** Two pure helpers in `src/genia/sheet.py`, built from existing helpers only: `sheet_sort_rows(before, sheet_value, invoke)` and `sheet_inner_join(left_key, right_key, right, left)`. Registration in `src/genia/builtins.py` follows `where` and `with_column` exactly: names imported in both import paths; a small documented closure `sort_rows_fn` calling the helper with `_invoke_raw_from_builtin`; `inner_join` registered directly; both as `_host_function_group("sort_rows", 2, …)` and `("inner_join", 4, …)` with `visibility="runtime-public"`. **V:** `set_host` alone reserves the name (`Env.is_runtime_owned`, environment.py); no separate reserved-name registry exists. A new closure must be documented (the code-documentation ratchet counts nested closures; `where_fn`/`derive_fn` are baselined gaps).

**Reused as-is (V):** `GeniaSheet`/`name_to_values`, `_freeze_column_name` (legality before lookup), `sheet_rows`, `_sheet_error`, `contains_protected` (already imported in sheet.py), `canonical_map_key` (function-local import, as `_freeze_column_name` does), `_invoke_raw_from_builtin`, `_host_function_group`. **Not introduced:** any equality, hashing or key-legality relation, direct Python callback calls, a `make_sheet` round trip, or a refactor.

**Sort (P; probed).** Sort a list of row indexes with the host's stable `<`-based sort. The key class defines only `__lt__(self, other)`. On each invocation, materialize two fresh row Lists in the same column order and pair shape as `sheet_rows`, then call `invoke(before, [row_i, row_j])`. Each row contains fresh name/cell pair containers with the exact stored cell references. Raise `_sheet_error("sort_rows expected comparator to return boolean")` unless the result is a `bool`. Rebuild each column tuple through the permutation. **V:** zero calls for n=0 and 1, exactly one for n=2, at least one for every n≥2 (all permutations to n=5); stable on ties and equal to a stable reference on 3,000 random strict weak orders; callback and non-boolean failures propagate from the sort with no partial Sheet; non-strict-weak comparators (random, always-true, cyclic) always yield a permutation (5,000 trials); `cmp_to_key` needs ~1.5× the calls. The host sort calls `later < earlier`; the contract leaves call order unspecified. Check order: Sheet, then `callable()` (the category `where` and `derive` use: lambdas, groups and builtins pass; Maps, Strings, Outcomes and Lists fail), then invocations. Both hosts construct fresh callback-visible rows and pairs for every invocation. Row indexes and immutable internal column references may be cached. Cell payloads, Outcomes, represented values and protected values retain their original references; this adds no portable object-identity operation. See the maintainer clarification on [#1346](https://github.com/m0smith/genia-2026/issues/1346#issuecomment-7197458391).

**Join (P).** Order matching contract section 3: (1) `isinstance` both Sheets, else `inner_join expected two Sheets` (not `_ensure_sheet`, whose text differs); (2) `_freeze_column_name` of the left key, then lookup in `left.name_to_values` (missing gives the contract message), then the same for the right; (3) distinct-names check over frozen left names versus right columns other than the right key; (4) key cells, left column in row order then right: `contains_protected` first (message `protected-value: inner-join key at <side> row <r>`), else `canonical_map_key` inside `try/except TypeError` raising `_sheet_error("inner_join expected a legal key at <side> row <r>") from None` so no host text or chained cause survives; (5) a dict from canonical right key to right row positions in order, then for each left row the matching positions; (6) output columns from stored names: all left columns at the left indexes, then right non-key columns at the right indexes, built directly as `GeniaSheet(tuple, row_count)` like `sheet_where`. **V:** `canonical_map_key` returns hashable tagged tuples with the contract's equalities (`1`, `1.0`, `float64(1.0)` share `('num',1)`; `1/2`, `0.5`, `float64(0.5)` share `('num-fraction',1,2)`; `true` is `('bool',True)`); `nil`, Outcomes, Maps, functions raise `TypeError` with host class names (hence the `from None` rewrite), NaN and protected carriers are rejected; a zero-column Sheet fails name resolution; the result is never zero-column. Complexity O(L + R + M + cells). Deep List keys can raise `RecursionError`, as for map keys; the contract normalizes only `TypeError`.

**Errors, none, pipeline (V).** First-`none` propagation comes from `invoke_callable` for any host group without `__genia_handles_none__`; the new names must not be added to `_NONE_AWARE_PUBLIC_FUNCTIONS`/`_SOME_AWARE_PUBLIC_FUNCTIONS`. `_sheet_error` sets `_genia_preserve_pipeline_error` (honored at evaluator.py:1109); comparator exceptions propagate unchanged. Wrong comparator arity fails only at invocation (`where` on a zero-row Sheet accepts a wrong-arity lambda).

**Guarded registration surfaces (V; the GREEN slice must include them).** R30's GREEN left guard tests red until its docs commit; R29's GREEN did not. Use the R29 shape: `src/genia/builtins.py`, `src/genia/sheet.py`, `src/genia/host_builtin_docs.py` (`_public` entries with the **correct** argument order; the existing `where`/`derive` entries are stale and out of scope), `hosts/python/mcp_worker_profile.py` `ALLOWED_BINDINGS` (pure, ALLOWED as R30 did), `tests/data/p1_host_binding_inventory.json`.

## 3. C++ host (genia-cpp)

**Facts (V).** Value kinds have no Symbol, Pair or Sheet. Natives are an if-chain `native_functions::call(name, args)` with no evaluator handle; precedents for a hook exist (`flow::Invoke`, and evaluator-intercepted `ref_update`/`cell_send`/`spawn`). The prelude is Genia source and is bounded by `kMaxCallDepth = 300`: `reduce`/`map` already fail at 300 elements, and a Genia-level stable merge sort is correct to 290 rows and `unsupported` from 300. Callback failures and wrong arity currently return `unsupported`, not an error. `==` on Outcomes and Represented values wrongly returns `false`. `map_key_encoding_checked` accepts only numbers, booleans and Strings (Lists, Outcomes, Maps and closures are rejected as unsupported). No `none` short-circuit exists anywhere in the call path (#1347).

**Callback design (P).** The C++ comparator follows the fresh-row and fresh-pair rule above. Native Sheet functions with an `Invoke` hook, in a new `src/sheet.hpp` exposing `sheet::dispatch(name, args, invoke, out)`, called from the three sites that call `dispatch_flow` (evaluator.hpp ~:111, :503, :940). The hook wraps `invoke_closure` directly so none cells reach callbacks as with `apply_raw`; it must not reuse `flow::apply`, which refuses none. The sort is a hand-written bounded stable merge sort (not `std::sort`, which is undefined behavior for non-strict-weak comparators; the contract promises only a permutation then). A prelude design over `apply_raw` is rejected: it caps near 295 rows and degrades to `unsupported`. Callback errors and wrong arity inside this dispatch must surface as normalized errors, not `unsupported`.

**Type names (P).** The contract's new diagnostics carry none. The 46 existing cases need the strings `string` and `list` (already rendered) and `GeniaSheet` (four `r29-existing-sheet-not-seq-*` cases), plus the arity diagnostic `No matching function: sheet_records/0. Available: sheet_records/1`. These belong to the #1330 Sheet core slice.

**Keys (P).** Relational keys need a local recursive key encoding: numbers (exact buckets, signed infinities), booleans, Strings, Symbols (after the Symbol slice) and recursive Lists. Outcomes, Maps and functions are illegal (normalized error); Represented values, which C++ cannot yet build, are not exercised. Matching uses the same exact numeric buckets as Python. List keys are included because the contract names a List-valued derived key as the multi-column idiom; a shared case covers it (matrix row `inner-join-list-key`), so the `sheet_relational` gap cannot be removed while C++ lacks it.

**Catalogue (V).** `genia2026_known_globals.hpp` is hand-kept (470 names); its header regeneration recipe is stale. Working recipe: regex `env\.(set_host|register_host_autoload|set_host_internal|set|set_internal|register_autoload)\(\s*"name"` over `src/genia/builtins.py` and `interpreter.py`. It adds `sheet_records` (the only public Python builtin missing), and R31 adds `sort_rows` and `inner_join`; otherwise C++ answers a false `Undefined name`.

**Re-pin mechanics (V).** genia-cpp pins genia-2026 in `ci.yml:35` (a shallow checkout whose `ref` must equal `kContractRevision`, else the runner exits 1), `src/protocol.hpp:58` (plus the hard-coded `known_capabilities()` list: a name must be added there before it can be declared, and only names the pinned manifest defines may be added; see section 2), `README.md:125,127` and the checked-in `evidence.json` (regenerated with `tools.spec_runner --host '<adapter>' --evidence`). genia-2026 pins genia-cpp in `host-parity.yml:65` and `docker-dev-environment.yml:42` (docker runs on README or docker path changes). Unmerged SHAs are fetchable and have precedent (R30 pinned reviewed candidates), and both repositories merge with merge commits so branch SHAs remain valid. Never squash or force-push a SHA that another repository pins.

## 4. Defect #1347 evidence and integration sequence

**Root cause area (V).** Ordinary-call dispatch evaluates arguments and never checks for `none`: `evaluator.hpp` Call (~:495-509), pipeline stage (~:921-946), flow wrapper (`flow.hpp:152`). The fix belongs at those call sites, not inside `invoke_closure` (which `apply_raw` and callbacks must keep raw), with an exemption set mirroring Python's none-aware names and none-pattern closures. Size S–M. **Not implemented in this phase.**

**What turns main red (V).** A new ungated shared spec that C++ fails turns genia-2026 `host-parity` red; a capability-gated spec does not; a genia-cpp pin bump to a revision containing such a spec turns genia-cpp CI red; genia-cpp `main` never goes red from specs merely landing in genia-2026 because its pin lags.

**Recommended sequence O2, paired merges (P; precedent V: R30 `r30-map2-global-alias`, genia-cpp #62).** (1) Commit A on a genia-2026 branch: ungated none-propagation specs only. **RED evidence:** run A against the unfixed adapter (`0c4dbb1`) and preserve the full runner output. A scratch prototype of this set already gives C++ `fail=5, pass=3` of 8 (ordinary call, second-argument none, first-none-wins, lambda and alias return `[5]` where Python returns `[none("a")]`; controls `apply_raw` delivery, `err` not propagated and `none?` pass) and Python 8/8. (2) genia-cpp branch: a C++-local RED test, the fix, and the re-pin of `ci.yml`, `kContractRevision`, `README.md:125/127` and `evidence.json` to A's SHA (the pin files are single-writer: this step starts after CPP-1 and re-pins from it); green; merge. (3) genia-2026 change B: bump the two pins to the genia-cpp merge SHA, sync docs; it merges A and B together with a merge commit. Freeze A (no rebase or force-push). No capability, no gap and no exception are introduced by the sequence itself, the spec is not weakened, and, provided the stated merge discipline is followed (A and B merge together with a merge commit; A frozen), main is never red. Commit A's exact spec list is fixed before RED and includes, beyond the eight prototype cases, a pipeline-stage case (`none("a") |> g`) and a none-aware user-closure case (a clause matching `none(r)`), because the fix sites include the pipeline stage and the none-aware exemption set. **V:** C++ answers `unsupported` for both today (Python gives `[none("a")]` and `["a"]`). If either is scoped out of #1347, its acceptance criterion 2 requires an issue-backed gap for it; the no-gap claim holds only if the full list passes. The related six hidden `r20-option-*` cases encode the same none-awareness rules and are the natural regression check. O1 (a temporary capability) and gating on a required capability are rejected: the first gates a baseline guarantee and leaves vocabulary behind; the second hides the spec and is invisible to the gate.

## 6. Findings that need a maintainer decision (no contract semantics change)

- **F1 — `r30-sheet-reserved` premise.** **V:** the source lowers to a closed declaration; Python's `_eval_closed_declaration` runs `_check_declaration` (the reserved-name error) before any annotation is evaluated, so `@meta` is never evaluated and `sentinel` never prints. The case therefore needs only a declaration-time reserved-name rejection for `=:` declarations on C++, not annotation evaluation and not #1261. This contradicts the premise of M3's `@meta` assignment and of keeping #1261 on the R31-A critical path. **V (reviewer):** C++ already parses and lowers the source to `IrClosedFuncDef` with an `IrAnnotation`, but evaluating any `=:` form is `unsupported`, even `x =: 1`; so the slice is an entry-scope evaluation path for `IrClosedFuncDef` that applies the Python runtime-owned-name check (needing the CPP-1 catalogue), with all other `=:` declarations staying `unsupported`. **Proposal:** that small slice (CPP-5 item) under #1330 (refs #1250/#1261), and #1261 moves to R31-B. **Fallback if F1 is not acknowledged:** the recorded assignments stand and slice CPP-5b (#1261 entry-scope `=:` evaluation and `@meta` evaluation per M3 and #1018) replaces the F1 item; CPP-6 then depends on CPP-5b and #1261 stays in R31-A.
- **F2 — contract §6 testability.** The sentence "shared conformance asserts only that [inherited name errors] fail" cannot be expressed by the runner. This design places those observations in Python host tests (matrix), a placement choice that leaves the contract's behavior unchanged. An optional wording clarification of the contract is available if you want it; none is assumed.
- **F3 — port removal wording.** The gap entries for `default_open_functions` and `closed_functions` require "every case listed" to pass; their gap lists include 9 and 11 `doc_help` cases (R33, unsupported), 39 and 5 `multi_file_eval` co-tagged cases, two `immutable_bindings` co-tagged cases in the default-open list, and, in the closed list, `model-b-closed-send-annotated-rejected`, which also requires `http_outbound_transport` (a separate contract-first release with no target). As written they cannot be removed before `doc_help`, `multi_file_eval`, `immutable_bindings` and an outbound-HTTP release land. Option (a): amend the removal text to "every listed case whose other required capabilities genia-cpp supports", with co-tagged cases accounted under their other capability (needs your acceptance, since it relaxes a recorded condition). Option (b): keep the wording and sequence `multi_file_eval` first, accepting that `doc_help` cases hold the two closures until R33 and `#1250` additionally until an outbound-HTTP release; **under (b), R31-B1 cannot complete within R31.** Recommended: (a).
- **F4 — callable category.** Contract §6 says "non-callable"; the design uses the host `callable()` check as `where` and `derive` do. Maps and Strings are ordinary callees (`_is_ordinary_callee`) but fail `callable()`; a spec pins the rejection and C++ native tests must match Python's category so no unevidenced divergence appears.
- **F5 — C++ gaps beyond the pre-flight.** List keys, Outcome `==` and Represented `==` are wrong or unsupported; the plan covers them (section 3, slices CPP-3/CPP-7).
- **F6 — contract §12 protected-key precedence.** Contract §12 says shared evidence must be able to observe protected-key versus illegal-key precedence. Protected values can be built from source in shared specs (ungated `r18-*` protected specs do it with `config_provider`/`secret_get`), but C++ has no protected values until R32 and would answer `unsupported`, which blocks the contract §8 condition that applicable specs pass for removal of the `sheet_relational` gap within R31. Option (a): keep a shared case and accept that the gap cannot be removed before C++ protected values (R32). Option (b): observe it in Python host tests until R32 and add the shared case then (recorded as an accounted deferral under the `config_protected` family targeted to R32 in `docs/strategy/roadmap/host-parity-ungated-cases.json` and the host-parity inventory). Recommended: (b); needs your decision because it moves one §12 observation out of shared evidence.
