# Python Code Reduction Review (genia-2026)

Reviewed 2026-08-28 against `src/genia/*.py` (~18,255 lines total, main branch). Goal: reduce line count / duplication while preserving external behavior. Two kinds of reduction are mixed into one list, ordered by estimated lines saved, descending — each item is tagged **[refactor]** (stays Python, restructures existing code) or **[→ Genia]** (moves logic out of `builtins.py` and into the `.genia` prelude, since the interpreter already exposes a small set of Python primitives and builds most public functions on top of them in `src/genia/std/prelude/*.genia`). All numbers are conservative estimates from a manual read, not a mechanical diff — verify before committing to any of these.

1. **[refactor] Collapse duplicated import-fallback blocks** — `lowering.py` (~5-182), `interpreter.py` (~20-150), `callable.py` (~12-64). Each file imports the same symbol set twice: once as `genia.X` (script-run fallback) and once as `.X` (package-relative), differing only by a leading dot. Replace with one import list behind a small `try/except ImportError` or a `_pkg = __package__ or "genia"` + `importlib.import_module` shim. ~180 lines saved. High confidence, but confirm nothing still runs these files as top-level scripts before dropping the fallback outright.

2. **[refactor] Table-driven `register_autoload` calls** — `builtins.py` ~4629-4863. 234 near-identical `env.register_autoload("name", arity, "std/prelude/X.genia")` calls. Group by prelude file into a `_autoload(path, *specs)` helper taking packed `(name, arity)` tuples. ~160-170 lines saved. High confidence, purely mechanical.

3. **[refactor] Shared annotation-binding scaffolding** — `server_cors_binding.py`, `server_config_binding.py`, `server_route_binding.py` (191/223/231 lines). Each defines its own `*Declaration`/`*BindingDiagnostic`/`*BindingResult` dataclasses and identical `_metadata_has` / `_metadata_get` / `_diagnostic` helpers plus the same candidate-sorting logic. Factor into a shared `_annotation_binding_support.py` with generic types, leaving only the domain-specific `validate_*_descriptor` per file. ~90-110 lines saved. Medium confidence — frozen dataclasses are typed per-domain elsewhere, so a thin generic/wrapper approach is safer than a full merge.

4. **[refactor] Deduplicate `_valid_*_error` validators** — `retrieval.py` (~246-278, 491-523, 753-785, 1011-1043). Four byte-identical functions (`_valid_embed_error`, `_valid_index_error`, `_valid_retrieve_error`, `_valid_rerank_error`) differing only by a string prefix; the error-kind sets are already aliased to the same object. Collapse into one `_valid_provider_error(prefix, value, timeout_ms)`. ~100 lines saved. High confidence.

5. **[refactor] Collapse duplicated import block in `evaluator.py`** — lines ~11-89. Same import list written twice (absolute vs. relative) for the same script/package fallback reason as #1. ~75 lines saved. High confidence.

6. **[refactor] Deduplicate `_validate_*_config` functions** — `retrieval.py` (~202-216, 419-431, 696-710, 968-982). Nearly identical embed/index/retrieve/rerank config validators (embed also checks `space`). One `_validate_provider_config(value, verb, extra_keys=())` helper. ~50 lines saved. High confidence.

7. **[refactor] Replace `_runtime_type_name` isinstance chain with a dispatch table** — `values.py` 13-80. 25+ sequential `isinstance` checks; most are 1:1 type→string. A `type(value)` dict lookup with a small fallback loop for subclass-sensitive cases (e.g. `GeniaOptionSome`/`GeniaMap`). ~35-40 lines saved. Medium confidence — must preserve bool-before-int ordering and a couple of string-based fallbacks.

8. **[refactor] Factor `construct_embed/index/retrieve/rerank` boilerplate** — `retrieval.py` (~397-413, 674-690, 946-962, 1166-1182). Each repeats: check provider type → validate config → check `GeniaProtected` credential → check `GeniaDeclassificationAuthority`. Generic `_construct_provider(kind, provider, provider_cls, config, credential, authority, validate_config, wrapper_cls)` factory. ~30 lines saved. Medium confidence.

9. **[refactor] `ast_nodes.py` dataclass boilerplate** — every one of ~35 node dataclasses repeats `span: SourceSpan | None = None`. Could be injected via a shared base or decorator. ~30 lines saved. Low priority/confidence — risks changing `__init__`/positional-construction signatures relied on by `parser.py`; only worth doing with a full call-site audit.

10. **[refactor] Extract shared vararg-resolution / ambiguous-function error logic** — `callable.py` (`GeniaFunctionGroup.__call__` ~235-256, `invoke_callable`'s `_resolve_target` ~719-761). Nearly identical matching + "No matching function" / "Ambiguous function resolution" error formatting. One shared `_resolve_group_target(functions, arity, label)` plus a shared error-formatter. ~25-30 lines saved. High confidence.

11. **[refactor] Deduplicate `_fail`/`_required`/`_require_identifier` validators** — `lifecycle_scope.py` (~130-198) and `lifecycle_plan.py` (~63-130). Identical bodies, differing only by an error-message prefix. Shared helper parameterized by a `kind` label. ~25-30 lines saved. Medium confidence — keep exact error strings if any tests assert them verbatim.

12. **[refactor] Factor `take`/`drop` fused-flow builders** — `callable.py` ~626-717. Shared iterator-wrapping/closing boilerplate (`consume`, exception tracking, `close_on_early_termination` finally-block) behind a parameterized `_bounded_flow(...)` helper. ~25 lines saved. Medium confidence — `take`'s count<=0 early return needs care.

13. **[refactor] Collapse `_reject_*_metadata_replacement` trio** — `evaluator.py` ~689-743. Four near-identical guards (`_reject_route_metadata_rebinding`, `_reject_route_metadata_replacement`, `_reject_server_metadata_replacement`, `_reject_cors_metadata_replacement`) parameterized only by an annotation key. One `_reject_metadata_replacement(name, metadata_or_annotations, key)`. ~20 lines saved. Medium confidence.

14. **[refactor] Table-driven `eval_binary` arithmetic/comparison dispatch** — `evaluator.py` ~1469-1516. Eight structurally identical `case OP: try/except TypeError` blocks. Dict of `op -> (operator.func, label)` with one shared try/except. ~20 lines saved. Medium confidence.

15. **[refactor] Table-driven simple `env.set(name, fn)` registrations** — `builtins.py` ~4370-4627. Six multi-line (4-line) registration call sites (`representation_match`, `refinement_match`, `open_shape_match`, `exact_shape_match`, `strip_representation`, `_diagnostic_skipped`) can collapse to single-line calls via a `_reg(name, arity, fn)` helper. ~18 lines saved. High confidence.

16. **[→ Genia] Move `cli_flag?`/`cli_option`/`cli_option_or` into `cli.genia`** — `builtins.py` ~2444-2458 (~15 Python lines). These are thin wrappers over map lookups already exposed as `map_get`/`map_has?` in `map.genia`. Sketch: `cli_option(opts, name) = map_get(opts, name)`; `cli_flag?(opts, name) = ...true -> true | _ -> false` built on `map_get`. ~15 Python lines removed for ~4 Genia lines added. Medium confidence — the `_UNSET` sentinel in `cli_option_or_fn` needs its absent/present semantics to survive the switch to `map_has?`/`map_get`, so check for the edge case where a stored value's shape could be misread as absent.

17. **[refactor] `GeniaCell`/`GeniaProcess` shared failure-state mixin** — `values.py` ~542-716. Both classes separately implement `_error_text` and lock/condition-guarded failed/error accessors. A small `_FailableWorker` mixin for the trivial shared parts. ~15 lines saved. Medium confidence.

18. **[refactor] Small `_kind_err(reason, kind)` helper for `GeniaOptionErr` context maps** — `retrieval.py`, ~15 recurring `_map(kind=symbol(...))` sites across embed/index/retrieve/rerank `__call__` methods. ~15 lines saved. Low confidence, modest win since call sites are already short.

19. **[→ Genia] Move `sum` into `math.genia`** — `builtins.py` `sum_fn` ~3013-3025 (~13 Python lines). Currently a hand-rolled loop validating each item and accumulating; could become `sum(xs) = reduce((acc, x) -> acc + x, 0, xs)`, reusing `reduce`/`+` (~1 Genia line). ~13 Python lines removed. Medium confidence — loses the precise "item N received type-X" error message and explicit `bool` rejection in favor of whatever error `+` raises on a bad operand; acceptable only if that degraded diagnostic is fine.

20. **[refactor] Give `IrNode` subclasses a `_children()` method / `CHILD_FIELDS`** instead of the long isinstance dispatch in `iter_ir_nodes` — `ir.py` ~306-371. More of a clarity win than a line-count win. ~10-15 lines saved. Low-medium confidence — must preserve exact DFS child order.

21. **[refactor] `diagnostic_error_fn` / `diagnostic_skipped_fn` duplication** — `builtins.py` ~2734-2756. Identical except for a `"kind"` symbol value; factor into `_make_diagnostic(kind)`. ~10 lines saved. High confidence.

23. **[refactor] `__genia_handles_none__` marker boilerplate** — `builtins.py`, 19 scattered one-line assignments across ~6 clusters. A `_mark_handles_none_all(*fns)` helper called once per cluster. ~9 lines saved. High confidence.

Composes already-exposed `entry_bytes`/`set_entry_bytes`: `update_entry_bytes(entry, updater) = set_entry_bytes(entry, updater(entry_bytes(entry)))` (1 Genia line). ~8 Python lines removed. 25. **[refactor] Minor `_failure`/`_error_result` tidy-up** — `server_lifecycle.py` ~125-152. Could reuse `_record` more tersely. ~5-10 lines saved. Low confidence/priority, cosmetic only.

26. **[→ Genia] Move `entry_json?` into a zip/archive prelude helper** — `builtins.py` ~4336-4338 (3 Python lines). `entry_json(entry) = ends_with(lower(entry_name(entry)), ".json")`, composing already-exposed `entry_name`/`lower`/`ends_with`. ~3 Python lines removed for 1 Genia line. High confidence, trivial, not a hot path.

## Totals
Realistic aggregate: roughly **840-940 lines** out of ~18,255 (~4.6-5.1%). The bulk (items 1-6, ~615-645 lines) is mechanical Python-to-Python deduplication with low risk: import-fallback blocks, autoload/registration tables, and near-identical validator functions across `retrieval.py` and the `server_*_binding.py` trio. The Genia-migration items (16, 19, 24, 26 — about 39 Python lines total) are a much smaller category: the codebase is already disciplined about keeping the Python primitive layer thin and pushing composition into the `.genia` prelude, so little pure-logic code is left in `builtins.py` that both (a) has no I/O/stdlib/concurrency/host-bridge dependency and (b) isn't already performance-sensitive (flows, actors, JSON/CSV/HTTP/zip machinery, `_map_*`/`_ref_*`/`_cell_*`/`_rng_*` state — all correctly left in Python). Each Genia move trades a small, specific diagnostic-message regression for fewer Python lines, so treat them as optional polish rather than priority work.

Method: four parallel subagent reviews covering builtins.py; retrieval.py/evaluator.py/parser.py; values.py/callable.py/interpreter.py/ir.py/lowering.py/model.py; and the remaining smaller modules (server_*, lifecycle_*, sheet.py, debug_controller.py, gemini_rest.py, host_bridge.py, lexer.py, test_cli.py, pattern_match.py, configuration.py, ast_nodes.py, utf8.py, _format_engine.py, environment.py, optimizer.py, cors_policy.py, native_test_*.py, test_kernel.py, errors.py, debug_protocol.py, docstrings.py), plus one follow-up pass specifically scanning builtins.py for pure-logic functions movable into the `.genia` prelude. No changes were made to the codebase — this is analysis only.
